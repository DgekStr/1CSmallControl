# Участие в проекте

Спасибо за интерес к **1C Small Control** — веб-порталу доступа к базам 1С.
Ниже — как сообщать о проблемах, предлагать улучшения и присылать изменения.

## Сообщить о проблеме

1. Проверьте, нет ли уже похожего [issue](https://github.com/DgekStr/1CSmallControl/issues).
2. Создайте новое issue по шаблону **Bug report**.
3. Приложите:
   - версию портала (видна в шапке и подвале) и версию платформы 1С;
   - шаги, которые привели к проблеме, и ожидаемое поведение;
   - скриншот и, если есть, запись из журнала: `journalctl -u 1c-portal -n 100`.

## Предложить улучшение

Создайте issue по шаблону **Feature request**: опишите задачу и пользу, а не только желаемую реализацию.

## Разработка

Проект — Flask + SQLite, без сборки фронтенда.

```bash
git clone https://github.com/DgekStr/1CSmallControl.git
cd 1CSmallControl

python3 -m venv .venv && . .venv/bin/activate
pip install flask

export PORTAL_DB="$PWD/portal.db"
export PORTAL_ADMIN_PASSWORD='локальный-пароль'
export PORTAL_SEED_DEMO=1
python3 app.py            # http://127.0.0.1:8080
```

Развёртывание на сервере и публикация баз 1С — в [README](README.md):

```bash
sudo PORTAL_SERVER_NAME=portal.example.ru PORTAL_ADMIN_PASSWORD='…' ./deploy.sh
```

### Структура

| Файл | Назначение |
|---|---|
| `app.py` | маршруты, схема БД, аутентификация, шлюз к публикациям 1С |
| `metrics.py` | метрики сервера для статистики |
| `templates/` | представления: вход, кабинет клиента, админка |
| `static/` | стили, скрипты, шрифты, логотипы |
| `tools/screenshot.js` | снимки экрана для документации |
| `*.sh` | развёртывание, публикация баз, обслуживание |

### Требования к коду

- Python 3.10+ (проверяется на 3.12), PEP 8, длина строки до 100 символов;
- шаблоны — Jinja2, без сторонних JS-фреймворков и внешних CDN;
- новый функционал покрывается проверкой на живом стенде (или описывается, как проверить);
- секреты (пароли, ключи, токены) **не попадают в репозиторий** — только через переменные окружения;
- персональные данные в скриншотах маскируются (`tools/screenshot.js`).

### Коммиты

Формат сообщений — [Conventional Commits](https://www.conventionalcommits.org/ru/):

```
feat(bases): открытие базы в новом окне
fix(gate): не подмешивать Content-Type Flask к ответам 1С
docs: раздел «Контур доступа»
```

### Pull request

1. Форкните репозиторий и создайте ветку от `main`.
2. Проверьте, что приложение запускается и затронутые страницы работают.
3. Заполните шаблон PR и приложите скриншоты изменений интерфейса.
4. Дождитесь ревью — замечания по стилю не блокируют, замечания по безопасности и доступу блокируют.

## Чего не делаем

- не добавляем зависимости без необходимости;
- не меняем поведение шлюза `/WEB/` без обсуждения — это контур доступа;
- не коммитим отчёты, дампы, базы и локальные конфигурации (см. `.gitignore`).
