# 1C-AI-Control v3.0.0 — промпт: ИИ-модуль в 1С (проверки баз)

> Рабочее название проекта: **1C-AI-Control v3.0.0**.
> Источник: `docs/ИИ/` (README, decisions, roadmap, detectors, tz-section).
> Основной MCP-промт — `prompt-mcp.md` в этой папке (копия `docs/ИИ/prompts-mcp.md`).
> Реализация — только по железным правилам, без исключений.

## 1. Назначение

ИИ-модуль — встроенный помощник для бухгалтеров и администраторов: проверка баз 1С,
поиск ошибок в данных, потерянных документов и типовых ошибок учёта.

**Главный принцип: ИИ никогда не работает с живой базой. Только с песочницей — её копией.**

## 2. Железные правила (не нарушаются никогда)

| № | Правило | Следствие |
|---|---|---|
| 1 | Только песочница | живая база недоступна ИИ ни на чтение, ни на запись |
| 2 | Песочница = копия одной базы (`1c-sandbox`) | в неё попадают только данные этой базы |
| 3 | Один ИИ-сеанс одновременно | вторая задача получает «песочница занята» |
| 4 | В песочнице только чтение (роль `SELECT`) | изменения данных невозможны |
| 5 | Каждый ответ помечен датой среза | «данные на 14.11.2026 03:00, песочница sb_…» |
| 6 | Все вызовы в аудит | кто, когда, база, запрос, ответ |
| 7 | Песочница живёт не дольше 7 дней | автоудаление |
| 8 | ПДн маскируются | ФИО, ИНН, СНИЛС → метки; суммы сохраняются |

## 3. Детекторы (минимум первой версии)

| Детектор | Что проверяет | Источник |
|---|---|---|
| `negative_stock` | отрицательные остатки | detectors.md |
| `dup_documents` | дубли документов (дата+сумма+контрагент) | detectors.md |
| `postings_gap` | разрывы нумерации / непроведённые документы | detectors.md |
| `amount_outliers` | аномальные суммы (выбросы) | detectors.md |
| `missing_counterparty` | контрагенты без реквизитов | detectors.md |
| `stale_balances` | зависшие сальдо | detectors.md |
| `tax_calc_check` | расхождения по НДС/налогам (настраиваемо) | tz-section.md |

Каждый детектор возвращает: `id`, `severity`, `count`, `examples[]` (до 10), `hint`, `query_hash`.

## 4. Пайплайн задачи

```
1. Пользователь выбирает базу и шаблон проверки (или пишет вопрос)
2. Панель проверяет право доступа к базе
3. Создаётся песочница (свежий дамп или существующая) → статус busy
4. Маскирование ПДн в выборках
5. Запрос к модели (облако) с жёстким системным промптом
6. Ответ → валидация (нет ли утечки ПДн, соблюдены ли правила)
7. Отчёт: PDF на сервере + краткая сводка в кабинете
8. Аудит (ai_task), удаление песочницы по TTL
```

## 5. Ограничения и лимиты

| Параметр | Значение |
|---|---|
| Задач на клиента в день | 5 |
| Срок хранения отчётов | 30 дней |
| Срез данных | 1 раз в сутки (ночной) |
| Модель | облачная, с маскированием ПДн |
| Стоимость на задачу | считать по токенам, лимит на клиента |

## 6. Что должно быть в интерфейсе

1. Карточка «ИИ-проверка» в кабинете клиента: выбор базы, шаблоны, история отчётов.
2. Индикатор занятости песочницы («сейчас работает проверка базы X»).
3. Отчёт: сводка, топ-10 проблем, ссылки на документы в 1С, дата среза.
4. Админ: очередь задач, лимиты, стоимость, аудит вызовов.

## 7. Этапы реализации

| Этап | Содержание | Результат |
|---|---|---|
| 1 | MCP-сервер + эксклюзивная песочница | API задач |
| 2 | Маскирование ПДн + системный промпт | безопасные выборки |
| 3 | Детекторы 1–3 | первые проверки |
| 4 | Отчёты PDF + кабинет | UI |
| 5 | Детекторы 4–7 | полный набор |
| 6 | Лимиты, биллинг, аудит | коммерческая готовность |

## 8. Оценка сроков

| Работа | Человек | С ИИ-агентом |
|---|---|---|
| MCP + песочница | 2 дня | 0,8 дня |
| Маскирование + промпты | 1,5 дня | 0,7 дня |
| Детекторы (7 шт) | 4 дня | 1,6 дня |
| Отчёты + кабинет | 1,5 дня | 0,7 дня |
| Лимиты/биллинг | 1 день | 0,4 дня |
| Тесты и приёмка | 1,5 дня | 0,8 дня |
| **Итого** | **11,5 дней** | **5 дней** |

## 9. Критерии приёмки

1. ИИ физически не может обратиться к живой базе (проверка в тестах).
2. В отчёте нет ПДн; есть дата среза и идентификатор песочницы.
3. Вторая параллельная задача блокируется.
4. Каждый вызов модели — в аудите с токенами и стоимостью.
5. Все 7 детекторов дают корректные результаты на тестовой базе.

## 10. Запреты

- Не подключать модель к продовой базе.
- Не отправлять полные таблицы без маскирования.
- Не хранить API-ключи модели в коде/репозитории.
- Не выполнять write-операции в песочнице.
