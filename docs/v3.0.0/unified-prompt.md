# 1C-AI-Control v3.0.0 — единый промпт и дорожная карта

> Рабочее название: **1C-AI-Control v3.0.0** (черновое — возможны дополнения).
> Единый документ: связаны два направления — отдельный сервис управления кластером и ИИ-модуль в 1С.
> Детальные задания: `prompt-cluster-service.md`, `prompt-ai-in-1c.md`.

## 1. Идея продукта

Коммерческий сервис управления парком 1С: панель на отдельном сервере + агенты на серверах 1С +
ИИ-проверки данных + аренда по базам. Технически — развитие рабочей версии 1C Small Control 2.1.2.

| Слой | Что делает | Где работает |
|---|---|---|
| Панель (UI/API) | базы, сеансы, бэкапы, пользователи, биллинг | отдельный сервер |
| Агент | привилегированные операции на сервере 1С | сервер 1С (systemd) |
| ИИ-модуль | проверки в песочнице | панель + агент |
| Кластер 1С | базы данных | сервер 1С (rac/ras 1545) |

## 3. Пошаговый план для ИИ-агента

### Шаг 1 — фундамент (0,5 дня)
1. Создать репозиторий `1c-ai-control` (или ветку `v3` в текущем).
2. `openapi.yaml`: `/status`, `/infobases`, `/sessions`, `/sessions/{sid}/terminate`,
   `/infobases/{uuid}/deny`, `/republish`, `/restart`, `/backup`, `/sandbox`, `/metrics`.
3. Схема токенов: агент-токен (32 байта, HMAC), IP-allowlist, аудит.

### Шаг 2 — агент, чтение (1 день)
1. Flask/FastAPI на `:8099`, systemd-юнит, `After=srv1cv8.service`.
2. Обёртки над `rac` (без шелла): `cluster list`, `infobase summary`, `session list`, `process list`.
3. Размеры БД (PG), службы, `df`, `smartctl`, IOPS-тест.
4. Кэш 5 с, таймауты 10 с, единый формат ошибок.

### Шаг 3 — агент, запись (1 день)
1. Белый список операций, каждая — отдельный endpoint с параметрами.
2. Идемпотентность `request_id`, журнал в `/var/log/1c-agent.log`.
3. Проверки безопасности: не более 1 рестарта в 5 минут, запрет при активных операциях.

### Шаг 4 — панель (1,5 дня)
1. Модель «серверы»: адрес агента, токен, статус.
2. Список баз/сеансов по всем серверам, фильтры, поиск.
3. Операции через агент, прогресс через polling/SSE.
4. Таймауты и деградация: агент недоступен → «сервер offline», без зависаний.

### Шаг 5 — бэкапы/песочницы (0,7 дня)
1. Расписание в панели → агент запускает `1c-backup`.
2. Песочницы: создание из дампа, TTL, автоудаление, проверка `pg_restore`.
3. Проверка восстановления раз в неделю (тестовая БД).

### Шаг 6 — мониторинг (0,4 дня)
1. Healthcheck: 1541/rmngr/rphost, RAS, HASP (`Loaded N licenses`), IOPS, место.
2. Алерты в Mattermost с троттлингом (1 сообщение на инцидент).

### Шаг 7 — ИИ (3 дня)
1. MCP-сервер + эксклюзивная песочница (1 задача).
2. Маскирование ПДн, системный промпт, валидация ответа.
3. Детекторы 7 шт., отчёты PDF, история 30 дней, лимит 5 задач/день.

### Шаг 8 — коммерция (0,4 дня)
1. Тарифы, лимиты по базам, месячная подписка, счёт.
2. Учёт токенов ИИ и стоимости на клиента.

### Шаг 9 — параллельный ввод и приёмка (1,6 дня)

> **Миграции нет.** Рабочая версия 2.1.2 остаётся на своём сервере и не трогается.
> Новая система ставится параллельно: отдельная ВМ под сервис + отдельный 1С-сервер (клон),
> связь между ними — по сети.

1. Поднять **отдельную ВМ** под 1C-AI-Control (панель + агент-контроллер), без 1С на борту.
2. Подготовить **клон 1С-сервера**: отдельная ВМ, агент, RAS 1545 открыт только для ВМ сервиса.
3. Настроить сетевую связь: агент на клоне, панель на своей ВМ, токены, allowlist по IP.
4. Опционально: перенести справочники портала (базы, пользователи, доступы) —
   это **не миграция**, а ручной перенос настроек; данные 1С не переносятся.
5. e2e: две площадки, отказ сети между ВМ, отказ агента, отказ кластера.
6. Чек-лист приёмки и передача.

## 4. Общие технические требования

| Требование | Значение |
|---|---|
| Язык | Python 3.11+ (единый стек с 2.1.2) |
| БД панели | SQLite (v3.0) → PostgreSQL (v3.1) |
| Транспорт | HTTPS, JSON, токены, аудит |
| Совместимость | 1С 8.3.20+ (RAS 10.0+), PostgreSQL Pro 1c |
| Развёртывание | systemd + venv, без Docker (по требованию — Docker) |
| Логи | journald + файлы, ротация |
| Наблюдаемость | `/healthz`, `/metrics` (Prometheus-формат) |

## 5. Риски

| Риск | Смягчение |
|---|---|
| Открытый RAS в сеть | только IP панели, ufw, токены |
| Агент = root | белый список, аудит, отдельный системный пользователь где возможно |
| ИИ утечёт ПДн | маскирование до отправки + валидация ответа |
| Долгий ввод | параллельная установка: 2.1.2 остаётся рабочей и не меняется |
| IOPS-ограничение дисков | NVMe под SQL (см. `docs/Server/`) |

## 6. Что считается готовностью v3.0.0

1. Панель управляет 1С на другом сервере без локального sudo.
2. ИИ-проверки работают в песочнице, отчёт PDF с датой среза.
3. Тарифы и лимиты действуют, аудит полон.
4. Ввод выполнен параллельно: старый сервер (2.1.2) не тронут, новые ВМ работают по сети.
5. Все тесты зелёные, есть инструкция для клиента.
