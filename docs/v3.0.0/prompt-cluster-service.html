1C-AI-Control v3.0.0 — промпт: отдельный сервис управления кластером 1С

Рабочее название проекта: 1C-AI-Control v3.0.0 (черновое, возможны дополнения).
Документ: задание для ИИ-агента на реализацию отдельного сервиса управления кластером 1С.

1. Цель

Вынести управление кластером 1С в самостоятельный сервис, работающий на любом сервере

(физическом или виртуальном) и управляющий одним или несколькими серверами 1С по сети.

Портал «1C Small Control» (v2.1.2) остаётся рабочей версией и становится первым клиентом сервиса.

3. Целевая архитектура

Развёртывание: панель и 1С-сервер — разные ВМ, связь только по сети.
Миграции с v2.1.2 нет: старый сервер остаётся рабочим, новый контур ставится параллельно.

┌──────────────────────┐         HTTPS          ┌────────────────────────┐
│  1C-AI-Control UI    │ ─────────────────────► │  Агент на сервере 1С   │
│  (веб-панель, Flask) │ ◄───────────────────── │  (HTTP+token, systemd) │
└──────────────────────┘     JSON + события     └────────────────────────┘
          │                                              │
          │ RAS 1545 (только чтение/управление сеансами)  │ rac, pg_dump, pg_restore
          ▼                                              ▼
   ┌──────────────┐                              ┌──────────────────┐
   │ Кластер 1С   │◄─────────────────────────────│ PostgreSQL       │
   └──────────────┘                              └──────────────────┘

Ключевое разделение:

  • UI/оркестратор — где угодно, без sudo, без локальных скриптов.
  • Агент — на сервере 1С, root-права, выполняет привилегированные операции.

5. Требования к панели

  1. Мульти-сервер: несколько серверов 1С, у каждого свой агент и RAS.
  2. Единый список баз по всем серверам, статус, размеры, сеансы.
  3. Операции: те же, что в v2.1.2, но через агент (без локального sudo).
  4. Мониторинг: healthcheck кластера, HASP-лицензии, IOPS, свободное место, бэкапы.
  5. Пользователи и роли: админ/оператор/клиент, доступ к базам, аудит.
  6. Публикации: управление default.vrd, .v8i, ссылками.
  7. Бэкапы: расписание, хранение, проверка восстановления, копии на SMB/NAS.
  8. Песочницы: создание копии базы, TTL, автоудаление, права.
  9. API: REST для интеграций + вебхуки (Mattermost, Telegram).

9. Критерии приёмки

  1. Панель на отдельном сервере управляет 1С на другом сервере (без локального sudo).
  2. Все операции v2.1.2 доступны удалённо и покрыты тестами.
  3. Агент не выполняет произвольные команды; каждый вызов — в аудите.
  4. Потеря связи агента → понятная ошибка, без «зависших» страниц.
  5. Отключение панели не влияет на работу 1С.

10. Запреты

  • Не открывать RAS (1545) в интернет; только панель по IP.
  • Не хранить пароли в открытом виде; только хэши/секреты в файле с 600.
  • Не давать агенту «shell по запросу» — только фиксированный набор команд.
  • Не удалять данные без подтверждения и бэкапа.
