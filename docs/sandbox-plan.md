# Песочница восстановления баз — дорожная карта

Задача: клиент из кабинета создаёт **отдельную копию** своей базы из ночного или ручного бэкапа,
работает в ней сколько нужно и не рискует боевыми данными. Боевая база не меняется никогда.

## Правила (согласованы)

| Параметр | Решение |
|---|---|
| Срок хранения | 3 дня по умолчанию, настраивается 1–14 (глобально) |
| Лимит | одна песочница на клиента (не на базу) |
| Удаление | клиент может удалить сам и создать новую с другой базы |
| Кто создаёт | все клиенты с доступом к базе |
| Что внутри | полноценный вход в 1С под своей учётной записью |
| Источник | любые копии: ночные и ручные («Запустить сейчас») |
| Предупреждения | окно с галочкой при создании + плашка «удалится завтра» |
| Уведомления | Mattermost админу: создание, удаление, ошибка |
| Автоочистка | при свободном месте < 8 ГБ удаляется самая старая песочница |
| Точечное восстановление документа | не делаем; смотреть и повторять вручную в боевой базе |

## Этап 0. Подготовка (0,5 ч)

- [ ] Настройки по умолчанию: `sandbox_enabled=0`, `sandbox_keep_days=3`, `sandbox_max_active=1`,
      `sandbox_min_free_gb=8`.
- [ ] Раздел «Восстановление баз» в админке (пока только чтение/сохранение настроек).
- [ ] Проверка, что `backup-status.json` и файлы в `/mnt/1cbackup` читаются порталом.
- [ ] Соглашение об именах: БД `<база>_restore_ГГГГММДД_ЧЧММ`, инфобаза и публикация — то же имя,
      клиенту показывается «Копия от ДД.ММ.ГГГГ (песочница)».

**Готово, если:** настройки сохраняются, карточка видна в «Настройке», фича выключена по умолчанию.

## Этап 1. MVP песочницы (9–10 ч)

### 1.1 Кабинет: выбор копии
- [ ] Кнопка **«Копии базы»** в карточке базы.
- [ ] Список копий этой базы: дата, размер, тип (ночная/ручная), «проверена».
- [ ] Копии старше срока хранения помечаются «устарела».

### 1.2 Предупреждение
- [ ] Окно: копия отдельная, боевая не меняется, данные на дату, песочница удалится через N дней,
      одновременно одна, изменения в песочнице не переносятся в боевую.
- [ ] Галочка «Понимаю» — без неё кнопка неактивна.

### 1.3 Восстановление
- [ ] Проверки: включена ли фича; есть ли уже песочница у клиента; свободное место (≥ 1,5× размера
      базы + 8 ГБ); целостность дампа (`pg_restore --list`); нет активных сеансов в целевой БД (её ещё нет).
- [ ] Создание БД, `pg_restore -Fc`, роль, инфобаза в кластере с этой БД, публикация.
- [ ] Запись в `access` для клиента, бейдж «песочница» в кабинете.
- [ ] Прогресс: «в очереди / восстановление / готово», обновление без перезагрузки страницы.
- [ ] Понятные ошибки: мало места, битый дамп, уже есть песочница, сервис выключен.

### 1.4 Жизнь песочницы
- [ ] Карточка в кабинете: «Копия от ДД.ММ (песочница)», «Открыть», «Удалить сейчас», осталось дней.
- [ ] Удаление клиентом: сеансы завершаются, инфобаза удаляется, БД и роль дропаются,
      публикация снимается, доступ удаляется.
- [ ] Журнал: `sandbox_create`, `sandbox_delete`, `sandbox_fail`.
- [ ] Mattermost админу: создана, удалена, ошибка.

**Готово, если:** клиент создаёт копию `test` на 07.11, заходит в неё (веб-клиент и тонкий клиент),
видит данные на дату, удаляет; боевая база при этом не меняется; в журнале и Mattermost есть записи.

## Этап 2. Обслуживание (3–4 ч)

- [ ] Таймер `1c-sandbox-tick` раз в час: удаляет просроченные, пишет статус.
- [ ] Плашка «Копия удалится завтра» (за 24 ч до удаления).
- [ ] Панель «Песочницы» в админке: кто, база, дата копии, размер, остаток дней, «Удалить сейчас».
- [ ] Автоочистка: свободно < 8 ГБ → удалить самую старую песочницу, уведомить владельца и админа.
- [ ] Статус в мониторинге: количество песочниц, занятое место.

**Готово, если:** просроченная песочница удаляется автоматически, плашка появляется за сутки,
при нехватке места освобождается самая старая, всё видно в админке.

## Этап 3. Позже (по запросу)

- «Сохранить песочницу как базу» — клиент решил, что данные нужны (≈3 ч).
- Точечное восстановление документа **через выгрузку из 1С в XML**, без SQL-вставок (≈3–4 ч).
- Заявка вместо кнопки: клиент просит, админ подтверждает (≈2 ч).
- Лимит суммарного места под песочницы (квота по клиенту).

## Риски и как закрываем

| Риск | Закрытие |
|---|---|
| Место на диске (26 ГБ свободно) | проверка перед стартом + автоочистка + лимит 1 песочница |
| Битый дамп | `pg_restore --list` перед восстановлением; при ошибке — удалить недоделанное |
| Клиент принял песочницу за боевую | бейдж «песочница», предупреждение, отдельный цвет карточки |
| Забытые песочницы | автоудаление по сроку + панель админа |
| Нагрузка на 1С при восстановлении | восстановление идёт в новую БД, кластер не блокируется |
| Откат фичи | выключатель `sandbox_enabled=0` в настройках |

## Тестовый план

1. `test` — маленькая база: создание, вход, удаление.
2. `dgek` — 1,1 ГБ: время восстановления, работа тонкого клиента.
3. Попытка второй песочницы → отказ с понятным текстом.
4. Выключенная фича → кнопки нет, прямой URL возвращает отказ.
5. Просроченная песочница → удаляется таймером, Mattermost-сообщение.
6. Заполнение диска (симуляция) → автоочистка.

## Порядок работ

| Когда | Что | Часы |
|---|---|---|
| Этап 0 + 1.1–1.2 | настройки, список копий, предупреждение | 4 |
| Этап 1.3 | восстановление, инфобаза, публикация, доступ | 4 |
| Этап 1.4 | карточка, удаление, журнал, Mattermost | 2 |
| Этап 2 | таймер, плашка, панель, автоочистка | 3–4 |
| Тесты 1–6 | прогон и исправления | 2 |
