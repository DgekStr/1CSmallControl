БП — блок «Учёт»

D1. Структура и битые ссылки 🔴

Что находит: ссылки на удалённые объекты, несоответствие версии конфигурации, «висячие» ссылки в реквизитах.

Проверка (1С):

// для каждого регистра/справочника — проверка целостности ссылок
ВЫБРАТЬ Ссылка ИЗ РегистрНакопления.ТоварыНаСкладах
  ГДЕ ВЫРАЗИТЬ(Номенклатура КАК СправочникСсылка.Номенклатура) = НЕОПРЕДЕЛЕНО

Результат: таблица Таблица · Ссылка · Реквизит, количество битых.

Как проверять исполнителю: на эталонной копии с искусственно удалённым объектом детектор должен его найти; повторять после каждого обновления конфигурации.

D2. Дубли справочников 🟡

Что находит: контрагенты, номенклатура, договоры с одинаковыми ИНН/КПП/номером.

Проверка (1С):

ВЫБРАТЬ ИНН, КОЛИЧЕСТВО(*) КАК Кол
ИЗ Справочник.Контрагенты ГДЕ НЕ ПометкаУдаления
СГРУППИРОВАТЬ ПО ИНН ИМЕЮЩИЕ КОЛИЧЕСТВО(*) > 1

Результат: пары/группы дублей с количеством документов у каждого.

Порог: ИНН заполнен; для номенклатуры — совпадение артикула + наименования.

D3. Пустые обязательные реквизиты 🟡

Что находит: документы без контрагента, организации, склада; МОЛ без физлица; банковский счёт без БИК.

Проверка (1С):

ВЫБРАТЬ Ссылка, Дата ИЗ Документ.РеализацияТоваровУслуг
ГДЕ Контрагент = НЕОПРЕДЕЛЕНО ИЛИ Организация = НЕОПРЕДЕЛЕНО

Результат: список документов с указанием пустого реквизита.

D4. Документы без движений 🟡

Что находит: проведённый документ, который не оставил движений ни по одному регистру.

Проверка (1С):

// сопоставление документов и движений в разрезе регистров
ВЫБРАТЬ Д.Ссылка ИЗ Документ.ПоступлениеТоваровУслуг КАК Д
ГДЕ Д.Проведён И НЕ Д.ПометкаУдаления
  И НЕ СУЩЕСТВУЕТ (ВЫБРАТЬ 1 ИЗ РегистрНакопления.ТоварыНаСкладах КАК Р
      ГДЕ Р.Регистратор = Д.Ссылка)

Результат: документы с датой, суммой, ожидаемыми регистрами.

D5. Движения без документов и отрицательные остатки 🔴

Что находит: «сиротские» движения (регистратор удалён) и отрицательные остатки по счетам/складам/количеству.

Проверка (1С):

// остатки
ВЫБРАТЬ Счёт, Склад, СУММА(КоличествоОстаток)
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки
СГРУППИРОВАТЬ ПО ... ИМЕЮЩИЕ СУММА(КоличествоОстаток) < 0

Результат: отрицательные остатки с документами-виновниками.

D6. Закрытие периода и расхождение БУ/НУ 🔴

Что находит: незакрытые месяцы, невыполненная последовательность расчётов, расхождения сумм БУ и НУ по счетам.

Проверка (1С):

// последовательности и закрытие
ВЫБРАТЬ Период ИЗ РегистрСведений.ЗакрытиеМесяцев
// расхождения
ВЫБРАТЬ Счёт, СУММА(СуммаБУ) - СУММА(СуммаНУ) КАК Разница
ИЗ РегистрБухгалтерии.Хозрасчёты ГДЕ ... СГРУППИРОВАТЬ ... ИМЕЮЩИЕ Разница <> 0

Результат: список незакрытых периодов + топ расхождений по счетам.

НДС — блок «Отчётность»

D7. Счета-фактуры и книги покупок/продаж 🔴

Что находит: счёт-фактура без реализации, реализация без счёта-фактуры, разрывы в нумерации, записи в книге без отражения в учёте.

Проверка (1С):

ВЫБРАТЬ Реализация.Ссылка ИЗ Документ.РеализацияТоваровУслуг КАК Реализация
ГДЕ Реализация.Проведён И Реализация.СуммаНДС > 0
  И НЕ СУЩЕСТВУЕТ (ВЫБРАТЬ 1 ИЗ Документ.СчётФактураВыданный КАК СФ
      ГДЕ СФ.ДокументОснование = Реализация.Ссылка)

Результат: несопоставленные документы, разрывы номеров, суммы расхождений.

Порог: только проведённые документы за период.

ЗУП — блок «Зарплата»

D8. Начисления, взносы и НДФЛ 🟡

Что находит: начисление без взносов, НДФЛ не совпадает с базой, выплаты без ведомости, взносы без начисления.

Проверка (1С):

ВЫБРАТЬ Сотрудник, Период, СуммаНачислений, СуммаВзносов
ИЗ РегистрНакопления.Начисления
// + сравнение с РегистрНакопления.СтраховыеВзносы и НДФЛ
ГДЕ ... СуммаНачислений > 0 И СуммаВзносов = 0

Результат: сотрудники и периоды с расхождением.

Особое: ПДн-риск — ФИО маскируются в отчёте, показываются только табельные номера.

Приёмка детекторов

ПроверкаКритерий
Ложные срабатывания≤ 10% на эталонной копии
Пропуск известных ошибок0 на тестовом наборе (по 3 ошибки на детектор)
Время≤ 30 с на детектор
ПДнФИО/ИНН маскируются, суммы сохраняются
Повторяемостьдва прогона дают одинаковый результат
Поддержкапосле обновления конфигурации перепроверка всех 8 детекторов

Порядок внедрения

ШагДействие
1D1–D3 (справочники, структура) — самые безопасные
2D4–D5 (движения, остатки) — основная ценность для бухгалтера
3D6 (закрытие периода) — сложнее, нужны последовательности
4D7 (НДС) — только после проверки на эталонном периоде
5D8 (ЗУП) — последним, отдельная база и отдельное соглашение по ПДн
