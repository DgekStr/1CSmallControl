## Назначение раздела

Определяет правила и состав работ по ИИ-модулю портала: проверка баз, поиск ошибок в данных,
поиск потерянных документов, разбор ошибок бухгалтера. Реализация — **не начата**, документ описывает
требования для исполнителя.

## Обязательные требования

| № | Требование |
|---|---|
| 1 | ИИ работает **исключительно с песочницей** (копией базы), созданной `1c-sandbox` |
| 2 | Одновременно — **только 1 песочница**, привязанная к 1 базе и 1 пользователю |
| 3 | Вторая попытка запуска ИИ получает ответ: «Песочница сейчас занята, попробуйте через 3 часа» |
| 4 | В песочнице разрешено **только чтение** (роль PostgreSQL `SELECT`) |
| 5 | Каждый ответ помечен датой среза данных и именем песочницы |
| 6 | Функция включается **администратором** в настройках пользователя |
| 7 | В **списке клиентов** рядом с именем включённого пользователя отображается **значок ИИ** |
| 8 | В **кабинете** у пользователя с включённым ИИ после создания песочницы появляется **кнопка-иконка ИИ** с диалогом, заданиями и отчётами |
| 9 | Все вызовы ИИ фиксируются в аудите (`action='ai_task'`) |
| 10 | Песочница живёт до 7 дней, далее удаляется автоматически |

## Механика блокировки песочницы

```text
Запуск ИИ пользователем А
  → песочница sb_<base>_<MMDDHHMM> закрепляется (busy, ttl=3 ч)
Попытка пользователя Б
  → «Песочница сейчас занята пользователем А (задача «<тип>», начата <время>).
     Попробуйте через 3 часа.»
По истечении 3 ч / после «Завершить»
  → блокировка снимается, песочница доступна
```

## UI — требования

| Место | Элемент | Условие показа |
|---|---|---|
| Админка → Пользователи → карточка | переключатель «ИИ-помощник» | всегда для админа |
| Админка → Клиенты (список) | значок ИИ рядом с именем | функция включена (🟢), выключена (⚪), занята (🟡) |
| Кабинет клиента → шапка | кнопка-иконка ИИ | функция включена **и** создана песочница |
| Кабинет → модалка ИИ | поле задачи, готовые задания, отчёты, карточка занятости, «Завершить» | после нажатия кнопки |

## Задачи для MCP (четыре сценария)

| Сценарий | Инструменты | Результат |
|---|---|---|
| Проверка базы | `check_structure`, `find_errors` | отчёт «Проблема / Количество / Пример / Критичность» |
| Поиск ошибок в данных | `ledger_diff`, `find_errors` | ошибки с объяснением и действиями бухгалтера |
| Потерянные документы | `find_missing_docs` | документы без движений, движения без документов |
| Ошибки бухгалтера | `run_select`, `explain_numbers` | первопричина + документ-виновник + что сделать |

Полные промты: [prompts-mcp.md](prompts-mcp.md) · Детекторы: [detectors.md](detectors.md)

## Критерии приёмки

1. ИИ физически не имеет доступа к живой базе (проверяется попыткой подключения — должно быть отказано).
2. Два пользователя не могут одновременно получить песочницу; второй видит корректный отказ.
3. В журналах MCP отсутствуют `INSERT/UPDATE/DELETE`.
4. Каждый ответ содержит дату среза и имя песочницы.
5. Бухгалтер без инструкции запускает «Проверить базу» и понимает отчёт.

## Что не входит в задачу

- Запись/исправление данных через ИИ.
- Работа ИИ с живой базой.
- Автоматическое принятие решений за бухгалтера.
- Обучение модели на данных без маскирования персональных данных.
