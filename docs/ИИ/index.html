1. Назначение

ИИ-модуль — встроенный в портал помощник для бухгалтеров и администраторов, который выполняет

проверки баз 1С, ищет ошибки в данных, потерянные документы и типовые ошибки учёта.

Главный принцип: ИИ никогда не работает с живой базой. Только с песочницей — её копией.

2. Железные правила (не нарушаются ни при каких условиях)

№ПравилоСледствие
1ИИ работает только в песочницеживая база не доступна ИИ ни на чтение, ни на запись
2Песочница — копия одной базы, созданная штатным 1c-sandboxв песочницу попадают только данные этой базы
3ИИ работает только с одной песочницей одновременновторая сессия получает ответ «песочница занята»
4В песочнице разрешено только чтение (роль SELECT)никакие изменения данных невозможны
5Каждый ответ ИИ помечен датой среза данных«данные на 11.11.2026 03:00, песочница sb_…»
6Все вызовы ИИ попадают в аудит порталакто, когда, какая база, какой запрос, что вернулось
7Песочница живёт не дольше 7 днейавтоудаление, освобождение места
8Персональные данные маскируются перед отправкой в модельФИО, ИНН, СНИЛС заменяются метками; суммы сохраняются (без них отчёт бесполезен)

3. Эксклюзивность песочницы

Одновременно с ИИ может работать только одна песочница и один пользователь.

Пользователь А запускает задачу ИИ
        │
        ▼
Песочница sb_dgekdb_11110300 закреплена за А (status = busy, ttl = 3 часа)
        │
Пользователь Б пытается запустить ИИ
        ▼
Ответ: «Песочница сейчас занята пользователем А (задача «поиск ошибок»,
       начата 11.11.2026 10:30). Попробуйте через 3 часа.»

Правила блокировки:

СитуацияПоведение
Песочница свободнасоздаётся/берётся свободная, ИИ запускается
Песочница занята другим пользователемотказ с текстом «занята, попробуйте через 3 часа»
Песочница занята текущим пользователемпродолжается его диалог
Истекли 3 часаблокировка снимается автоматически, песочница помечается stale
Пользователь нажал «Завершить»блокировка снимается сразу

3.1. Обязательное условие запуска — доступ к базе

Флаг ИИ сам по себе не даёт права проверить базу. Срез создаётся только по базе,

где у пользователя есть строка в access. Иначе — отказ «нет доступа к базе».

СитуацияПоведение
Флаг ИИ есть, доступ к базе естьсрез создаётся, задача выполняется
Флаг ИИ есть, доступа к базе нетотказ, запись в аудит
Флага неткнопка ИИ в кабинете не отображается

3.2. Срез данных — «Песочница ИИ»

ПараметрЗначение
Кнопка«Песочница ИИ» в кабинете (шапка, кнопка 🤖)
Частотане чаще 1 раза в сутки на пользователя
Повторный запуск«сегодняшний срез создан в HH:MM, используем его»
Время создания5–15 минут (копия ~1,8 ГБ)
Удержаниеблокировка 3 часа, затем освобождается
Хранение песочницыавтоудаление, чтобы не забить диск

4. Включение функции

4.1. Админка → Пользователи

Функция включается только администратором, для конкретного пользователя:

Админка → Пользователи → [пользователь] → Настройки → «ИИ-помощник»: вкл/выкл

В списке клиентов рядом с именем пользователя отображается значок ИИ:

ОтображениеЗначение
🟢 значок ИИфункция включена и доступна
⚪ значок перечёркнутфункция выключена
🟡 значок с точкойпесочница занята / задача выполняется

4.2. Кабинет клиента

У пользователя с включённым ИИ после создания песочницы в кабинете появляется

кнопка-иконка ИИ (в стиле остальных кнопок шапки, рядом с конвертом обратной связи).

Кабинет → шапка → [✉ обратная связь] [🤖 ИИ] [⚙ настройки] [⎋ выход]
                     │
                     ▼
        Диалог ИИ: поле задачи, список заданий, отчёты
ЭлементЧто делает
Поле задачисвободный текст: «найди ошибки в реализации», «почему не закрывается месяц»
Список заданийготовые сценарии: проверка базы, поиск ошибок, потерянные документы, ошибки бухгалтера
Отчётрезультат с таблицей, ссылкой на песочницу и датой среза
Карточка занятостикто занимает песочницу и до какого времени
Кнопка «Завершить»снимает блокировку, освобождает песочницу

Если песочницы нет — кнопка ИИ неактивна с подсказкой «Сначала создайте песочницу».

6. Техническая схема

Живая база dgek-db
      │  ночью / по запросу (1c-sandbox create)
      ▼
Песочница sb_dgekdb_MMDDHHMM   →  PostgreSQL (роль SELECT)
      │
      ▼
MCP-сервер (Python, отдельный сервис)
      │  инструменты: check_structure, find_errors, find_missing_docs, explain_ledger
      ▼
LLM (локальная модель или шлюз с маскированием ПДн)
      │
      ▼
Кабинет портала: диалог + отчёт + аудит

8. Аудит

Каждое действие пишется в audit:

action = 'ai_task'
actor  = логин пользователя
details = "<тип задачи> | песочница <имя> | база <slug> | строк <n> | <результат>"

Администратор видит журнал: Админка → Журнал заданий сервера → ИИ-задачи.
