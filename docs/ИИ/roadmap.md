# Дорожная карта ИИ-модуля (MCP-помощник для бухгалтеров)

> **Документ обновлён 12.11.2026 (v1.1).** Актуальные решения — в [decisions.md](decisions.md):
> только облако с маскированием ПДн · 1 срез в сутки · PDF на сервере · 5 задач/день ·
> отчёты 30 дней · проверка доступа к базе обязательна · детекторы — [detectors.md](detectors.md).

Версия: **1.1** · Дата: 12.11.2026 · Горизонт: 7–9 недель

| Этап | Название | Срок | Результат |
|---|---|---|---|
| 0 | Подготовка и правила | 3–4 дня | согласованы правила, схема, места хранения |

Итого: **7–9 недель** (60% времени — детекторы и запросы под конфигурации, не MCP).

## Этап 0. Подготовка и правила

| Задача | Результат |
|---|---|
| Согласовать правила из `README.md` | подтверждение «только песочницы» — **согласовано** |
| Определить LLM | **только облако с маскированием** (локальная модель — после пилота) |
| Выбрать базы для пилота | первая: `dgek-db` (БП) |
| Определить размещение LLM | локально или шлюз с маскированием |
| Выделить место под песочницы | +20–30 ГБ или отдельный диск |
| Создать роль БД `usr_ai_read` | только `SELECT` |
| Зафиксировать шаблон отчёта | таблица + дата среза + песочница |

**Критерий готовности:** правила подписаны, место выделено, роль создана.

## Этап 1. MCP-сервер и эксклюзивная песочница

| Задача | Детали |
|---|---|
| MCP-сервер на Python | отдельный systemd-сервис `1c-ai-mcp`, порт только localhost |
| Список инструментов | `list_sandboxes`, `use_sandbox`, `release_sandbox`, `run_query` (read-only) |
| Блокировка песочницы | `sandbox_lock` таблица: sandbox_id, user_id, task, started_at, expires_at (3 часа) |
| Ответ при занятости | «Песочница сейчас занята — попробуйте через 3 часа» + кто и до когда |
| Автоосвобождение | таймер каждые 5 минут: просроченные блокировки снимаются |
| Создание песочницы по требованию | вызов `1c-sandbox create <base>`, ожидание готовности |

**Критерий готовности:** два пользователя одновременно не могут получить одну песочницу; второй видит корректный отказ.

## Этап 2. Детекторы ошибок (основа ценности)

Состав детекторов и формулировки проверок на языке 1С — в [detectors.md](detectors.md).
Владелец детекторов: **администратор портала**; после каждого обновления конфигурации — перепроверка всех 8.

| № | Детектор | Что находит |
|---|---|---|
| 1 | Структура и битые ссылки | ссылки на удалённые объекты, несоответствия версии конфигурации |
| 2 | Дубли | контрагенты, номенклатура, документы по номеру+дате |
| 3 | Пустые обязательные реквизиты | контрагент без ИНН, документ без организации |
| 4 | Документы без движений | проведён, но нет проводок/движений по регистрам |
| 5 | Движения без документов | «сиротские» движения регистров |
| 6 | Отрицательные остатки | по счетам, складам, по количеству |
| 7 | Расхождение БУ и НУ | суммы бухгалтерского и налогового учёта |
| 8 | Незакрытые периоды | отсутствие закрытия месяца, последовательность |

**Критерий готовности:** на эталонной копии каждый детектор даёт отчёт с числом находок и примерами строк.

## Этап 3. Поиск потерянных документов

| Сценарий | Логика |
|---|---|
| Документ есть, но не влияет на учёт | проверка проведения и регистров |
| Сумма не сходится с первичкой | сверка итогов документов и регистров |
| Запись есть в одном регистре, нет в другом | перекрёстная сверка регистров |
| Документ удалён, но следы остались | поиск «висячих» движений и ссылок |

**Критерий готовности:** каждый сценарий воспроизводится на тестовом примере с заранее известным ответом.

## Этап 4. Диалог и отчёты в кабинете

| Задача | Детали |
|---|---|
| Кнопка ИИ в шапке | появляется только при включённой функции |
| Кнопка «Песочница ИИ» | живой срез базы, **не чаще 1 раза в сутки**, создание 5–15 мин |
| PDF | отчёт формируется **на сервере (LibreOffice)** |
| Модалка диалога | поле задачи, список готовых заданий, история |
| Готовые задания | «Проверить базу», «Найти ошибки», «Найти потерянные документы», «Почему не закрывается месяц» |
| Отчёт | таблица находок + дата среза + имя песочницы + **PDF** |
| Подтверждение находок | бухгалтер отмечает «верно / ложное» по каждой находке |
| Карточка занятости | кто держит песочницу, до какого времени |
| Кнопка «Завершить» | снимает блокировку |

**Критерий готовности:** бухгалтер без инструкции запускает проверку и понимает отчёт.

## Этап 6. Аудит, лимиты, персональные данные

| Задача | Детали |
|---|---|
| Аудит | `action='ai_task'` со всеми параметрами |
| Маскирование | ФИО/ИНН/СНИЛС → метки перед отправкой в LLM; суммы сохраняются |
| Лимиты | 30 с на запрос, 10 000 строк, 5 задач/день, задача до 30 мин |
| Срок жизни песочницы | 7 дней, автоудаление |
| Политика хранения отчётов | **30 дней** |

**Критерий готовности:** отчёт аудита показывает полную цепочку «пользователь → песочница → запрос → результат».

## Этап 7. Пилот

| Задача | Детали |
|---|---|
| Круг участников | 1–2 бухгалтера на `dgek-db` |
| Сбор вопросов | 20 реальных вопросов от бухгалтеров |
| Метрика | доля ответов, признанных полезными (цель ≥ 60%) |
| Решение | продолжать / дорабатывать детекторы / остановить |

**Критерий готовности:** есть метрика полезности и решение по развитию.

## Риски и ответы

| Риск | Мера |
|---|---|
| Песочницы съедят диск | одна песочница, 7 дней, автоудаление |
| LLM придумает цифру | каждый ответ со ссылкой на запрос и датой среза |
| Детекторы сломаются после обновления конфигурации | версионирование запросов, тесты на эталонной копии |
| ПДн уйдут в облако | локальная модель или маскирование |
| Нет спроса у бухгалтеров | пилот на 20 вопросах до полноценной разработки |

## Что нельзя делать на любом этапе

1. Подключать ИИ к живой базе.
2. Разрешать два параллельных ИИ-сеанса.
3. Выполнять запись в песочницу через ИИ.
4. Отдавать ответ без указания даты среза и песочницы.
