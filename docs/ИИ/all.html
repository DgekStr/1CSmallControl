Правила

ИИ-модуль портала 1C Small Control — правила работы

Документ обновлён 12.11.2026 (v1.1). Актуальные решения — в decisions.md:

Версия документа: 1.1 · Дата: 12.11.2026 · Статус: проект (реализация не начата)

1. Назначение

ИИ-модуль — встроенный в портал помощник для бухгалтеров и администраторов, который выполняет

проверки баз 1С, ищет ошибки в данных, потерянные документы и типовые ошибки учёта.

Главный принцип: ИИ никогда не работает с живой базой. Только с песочницей — её копией.

2. Железные правила (не нарушаются ни при каких условиях)

№ПравилоСледствие
1ИИ работает только в песочницеживая база не доступна ИИ ни на чтение, ни на запись
2Песочница — копия одной базы, созданная штатным 1c-sandboxв песочницу попадают только данные этой базы
3ИИ работает только с одной песочницей одновременновторая сессия получает ответ «песочница занята»
4В песочнице разрешено только чтение (роль SELECT)никакие изменения данных невозможны
5Каждый ответ ИИ помечен датой среза данных«данные на 11.11.2026 03:00, песочница sb_…»
6Все вызовы ИИ попадают в аудит порталакто, когда, какая база, какой запрос, что вернулось
7Песочница живёт не дольше 7 днейавтоудаление, освобождение места
8Персональные данные маскируются перед отправкой в модельФИО, ИНН, СНИЛС заменяются метками; суммы сохраняются (без них отчёт бесполезен)

3. Эксклюзивность песочницы

Одновременно с ИИ может работать только одна песочница и один пользователь.

Пользователь А запускает задачу ИИ
        │
        ▼
Песочница sb_dgekdb_11110300 закреплена за А (status = busy, ttl = 3 часа)
        │
Пользователь Б пытается запустить ИИ
        ▼
Ответ: «Песочница сейчас занята пользователем А (задача «поиск ошибок»,
       начата 11.11.2026 10:30). Попробуйте через 3 часа.»

Правила блокировки:

СитуацияПоведение
Песочница свободнасоздаётся/берётся свободная, ИИ запускается
Песочница занята другим пользователемотказ с текстом «занята, попробуйте через 3 часа»
Песочница занята текущим пользователемпродолжается его диалог
Истекли 3 часаблокировка снимается автоматически, песочница помечается stale
Пользователь нажал «Завершить»блокировка снимается сразу

3.1. Обязательное условие запуска — доступ к базе

Флаг ИИ сам по себе не даёт права проверить базу. Срез создаётся только по базе,

где у пользователя есть строка в access. Иначе — отказ «нет доступа к базе».

СитуацияПоведение
Флаг ИИ есть, доступ к базе естьсрез создаётся, задача выполняется
Флаг ИИ есть, доступа к базе нетотказ, запись в аудит
Флага неткнопка ИИ в кабинете не отображается

3.2. Срез данных — «Песочница ИИ»

ПараметрЗначение
Кнопка«Песочница ИИ» в кабинете (шапка, кнопка 🤖)
Частотане чаще 1 раза в сутки на пользователя
Повторный запуск«сегодняшний срез создан в HH:MM, используем его»
Время создания5–15 минут (копия ~1,8 ГБ)
Удержаниеблокировка 3 часа, затем освобождается
Хранение песочницыавтоудаление, чтобы не забить диск

6. Техническая схема

Живая база dgek-db
      │  ночью / по запросу (1c-sandbox create)
      ▼
Песочница sb_dgekdb_MMDDHHMM   →  PostgreSQL (роль SELECT)
      │
      ▼
MCP-сервер (Python, отдельный сервис)
      │  инструменты: check_structure, find_errors, find_missing_docs, explain_ledger
      ▼
LLM (локальная модель или шлюз с маскированием ПДн)
      │
      ▼
Кабинет портала: диалог + отчёт + аудит

Каждое действие пишется в audit:

action = 'ai_task'
actor  = логин пользователя

Администратор видит журнал: Админка → Журнал заданий сервера → ИИ-задачи.

1. Системный промт (общий для всех задач)

Ты — ИИ-помощник портала «1C Small Control» для бухгалтеров.

ЖЁСТКИЕ ПРАВИЛА:
1. Ты работаешь ТОЛЬКО с песочницей (копией базы). Живая база тебе недоступна.
   Срез создаётся не чаще 1 раза в сутки; на отчёте указывай его время.
2. Ты НЕ изменяешь данные: только чтение и анализ.
3. Каждый ответ начинай со строки:
   «Данные на <дата среза> · песочница <имя> · база <название>».
4. Каждую цифру сопровождай ссылкой на инструмент/запрос, которым она получена.
5. Если данных недостаточно — так и скажи, не додумывай.
6. Персональные данные показывай только в объёме, нужном для ответа.
7. Если пользователь просит исправить данные — объясни, что правки вносятся
   в 1С человеком, и покажи, что именно надо исправить.
9. Для каждой находки проси подтверждение: «верно / ложное» (бухгалтер отмечает сам).
10. Лимит — 5 задач в день, одна задача до 30 минут; при превышении откажи вежливо.
8. Отвечай на русском, кратко, структурированно: таблица находок + пояснение.

3. Задание 1. Проверка базы

Промт:

Задача: проверить базу в песочнице и дать заключение.

Шаги:
1. sandbox_info — зафиксируй дату среза.
2. check_structure — проверь структуру и битые ссылки.
3. find_errors с kinds = ["duplicates","empty_required","negative_balances"].
4. Сформируй отчёт: таблица «Проблема | Количество | Пример | Критичность».
5. Заверши выводом: «Критичных ошибок: N. Рекомендация: …».

Формат отчёта:
| Проблема | Найдено | Пример | Критичность |
|---|---|---|---|

Критерий приёмки: отчёт содержит дату среза, песочницу, число находок по каждой проверке и примеры.

4. Задание 2. Поиск ошибок в данных

Промт:

Задача: найти ошибки ведения учёта за <период>.

Шаги:
1. ledger_diff за период — расхождения БУ и НУ.
2. find_errors kinds = ["unposted","negative_balances","empty_required"].
3. Для каждой находки: почему это ошибка и что проверить бухгалтеру.
4. Сгруппируй по критичности: блокирующие закрытие / искажающие отчётность / косметические.

Ответ: таблица + список действий бухгалтера (без изменения данных).

Критерий приёмки: у каждой находки есть объяснение «почему это ошибка» и имя документа/операции.

5. Задание 3. Поиск потерянных документов

Промт:

Задача: найти документы, которые «потерялись» — не влияют на учёт.

Шаги:
1. find_missing_docs scenario = "doc_without_moves" — документы без движений.
2. find_missing_docs scenario = "moves_without_doc" — движения без документов.
3. Для каждого документа: сумма, дата, контрагент, чего не хватает.
4. Проверь, не дублируются ли суммы (двойной учёт).

Ответ: таблица «Документ | Дата | Сумма | Что не так | Что проверить».

Критерий приёмки: на эталонном примере с известным «потерянным» документом ИИ его находит.

6. Задание 4. Ошибки бухгалтера

Промт:

Задача: объяснить ошибку бухгалтера и показать первопричину.

Шаги:
1. Прими вопрос пользователя (например: «почему не закрывается месяц»).
2. Определи, какие проверки нужны (не запускай всё подряд).
3. Запусти 1–3 инструмента и собери факты.
4. Объясни причину простыми словами, со ссылкой на документ и дату.
5. Предложи конкретное действие бухгалтера (записать, перепровести, исправить реквизит).

Запрещено: выдумывать номера документов и суммы; если данных нет — сказать «не найдено».

Критерий приёмки: ответ содержит первопричину, документ-виновник и последовательность действий.

6.1. Задание 5. Закрытие периода перед отчётностью

Задача: проверить готовность базы к закрытию месяца за <период>.
Шаги: ledger_diff за период → find_errors kinds=["unposted","negative_balances"] →
      D6-детектор закрытия (см. detectors.md).
Ответ: блокирующие проблемы / что мешает закрытию / что проверить; список действий.

6.2. Задание 6. Сверка взаиморасчётов с контрагентом

Задача: сверить расчёты с <контрагент> за <период>.
Шаги: обороты по 60/62/76 в разрезе документов → сопоставление с актами →
      поиск расхождений и непроведённых документов.
Ответ: таблица «Документ | Дата | Сумма | Учёт | Расхождение».

6.3. Задание 7. НДС — счета-фактуры и книги

Задача: проверить НДС за <период> (детектор D7).
Шаги: реализация без СФ → СФ без реализации → разрывы нумерации → сверка книг.
Ответ: список несопоставленных документов с суммами НДС и критичностью.

6.4. Задание 8. Зарплата (ЗУП)

Задача: проверить начисления и взносы за <период> (детектор D8).
Шаги: начисления без взносов → НДФЛ vs база → выплаты без ведомости.
Ответ: табельные номера (без ФИО), периоды и суммы расхождений.

6.5. Подтверждение находок

Каждая находка в отчёте сопровождается полем:

[ ] верно   [ ] ложное

Отметки сохраняются в портале и используются для настройки детекторов.

Раздел ТЗ: ИИ-модуль (MCP-помощник) — только песочницы

только облако с маскированием ПДн · 1 срез в сутки · PDF на сервере · 5 задач/день ·

Назначение раздела

Определяет правила и состав работ по ИИ-модулю портала: проверка баз, поиск ошибок в данных,

поиск потерянных документов, разбор ошибок бухгалтера. Реализация — не начата, документ описывает

требования для исполнителя.

Обязательные требования

№Требование
1ИИ работает исключительно с песочницей (копией базы), созданной 1c-sandbox
2Одновременно — только 1 песочница, привязанная к 1 базе и 1 пользователю
3Вторая попытка запуска ИИ получает ответ: «Песочница сейчас занята, попробуйте через 3 часа»
4В песочнице разрешено только чтение (роль PostgreSQL SELECT)
5Каждый ответ помечен датой среза данных и именем песочницы
6Функция включается администратором в настройках пользователя
7В списке клиентов рядом с именем включённого пользователя отображается значок ИИ
8В кабинете у пользователя с включённым ИИ после создания песочницы появляется кнопка-иконка ИИ с диалогом, заданиями и отчётами
9Все вызовы ИИ фиксируются в аудите (action='ai_task')
10Песочница живёт до 7 дней, далее удаляется автоматически

Механика блокировки песочницы

Запуск ИИ пользователем А
  → песочница sb_<base>_<MMDDHHMM> закрепляется (busy, ttl=3 ч)
Попытка пользователя Б
  → «Песочница сейчас занята пользователем А (задача «<тип>», начата <время>).
     Попробуйте через 3 часа.»
По истечении 3 ч / после «Завершить»
  → блокировка снимается, песочница доступна

Критерии приёмки

  1. ИИ физически не имеет доступа к живой базе (проверяется попыткой подключения — должно быть отказано).
  2. Два пользователя не могут одновременно получить песочницу; второй видит корректный отказ.
  3. В журналах MCP отсутствуют INSERT/UPDATE/DELETE.
  4. Каждый ответ содержит дату среза и имя песочницы.
  5. Бухгалтер без инструкции запускает «Проверить базу» и понимает отчёт.

Сроки и состав

Дорожная карта: roadmap.md — 7–9 недель, из них 60% — детекторы под конфигурации.

Что не входит в задачу

  • Запись/исправление данных через ИИ.
  • Работа ИИ с живой базой.
  • Автоматическое принятие решений за бухгалтера.
  • Обучение модели на данных без маскирования персональных данных.

Детекторы

ТЗ на детекторы ошибок 1С (БП + НДС + ЗУП)

Версия: 1.1 · Дата: 12.11.2026 · Владелец: администратор портала

Статус: проект · Выполняется только в песочнице (копии базы), режим read-only

Общие правила для всех детекторов

ПравилоТребование
Источник данныхпесочница, срез не старше суток
Язык проверкиштатные запросы 1С (HTTP-сервис в копии), не прямой SQL по _inforg*
Лимитдо 30 с на детектор, до 10 000 строк результата
Формат находкитип · документ/объект · дата · сумма · критичность · что сделать

Критичность: 🔴 блокирует отчётность · 🟡 искажает данные · ⚪ косметика.

БП — блок «Учёт»

D1. Структура и битые ссылки 🔴

Что находит: ссылки на удалённые объекты, несоответствие версии конфигурации, «висячие» ссылки в реквизитах.

Проверка (1С):

// для каждого регистра/справочника — проверка целостности ссылок
ВЫБРАТЬ Ссылка ИЗ РегистрНакопления.ТоварыНаСкладах
  ГДЕ ВЫРАЗИТЬ(Номенклатура КАК СправочникСсылка.Номенклатура) = НЕОПРЕДЕЛЕНО

Результат: таблица Таблица · Ссылка · Реквизит, количество битых.

Как проверять исполнителю: на эталонной копии с искусственно удалённым объектом детектор должен его найти; повторять после каждого обновления конфигурации.

D2. Дубли справочников 🟡

Что находит: контрагенты, номенклатура, договоры с одинаковыми ИНН/КПП/номером.

Проверка (1С):

ВЫБРАТЬ ИНН, КОЛИЧЕСТВО(*) КАК Кол
ИЗ Справочник.Контрагенты ГДЕ НЕ ПометкаУдаления
СГРУППИРОВАТЬ ПО ИНН ИМЕЮЩИЕ КОЛИЧЕСТВО(*) > 1

Результат: пары/группы дублей с количеством документов у каждого.

Порог: ИНН заполнен; для номенклатуры — совпадение артикула + наименования.

D3. Пустые обязательные реквизиты 🟡

Что находит: документы без контрагента, организации, склада; МОЛ без физлица; банковский счёт без БИК.

Проверка (1С):

ВЫБРАТЬ Ссылка, Дата ИЗ Документ.РеализацияТоваровУслуг
ГДЕ Контрагент = НЕОПРЕДЕЛЕНО ИЛИ Организация = НЕОПРЕДЕЛЕНО

Результат: список документов с указанием пустого реквизита.

D4. Документы без движений 🟡

Что находит: проведённый документ, который не оставил движений ни по одному регистру.

Проверка (1С):

// сопоставление документов и движений в разрезе регистров
ВЫБРАТЬ Д.Ссылка ИЗ Документ.ПоступлениеТоваровУслуг КАК Д
ГДЕ Д.Проведён И НЕ Д.ПометкаУдаления
  И НЕ СУЩЕСТВУЕТ (ВЫБРАТЬ 1 ИЗ РегистрНакопления.ТоварыНаСкладах КАК Р
      ГДЕ Р.Регистратор = Д.Ссылка)

Результат: документы с датой, суммой, ожидаемыми регистрами.

D5. Движения без документов и отрицательные остатки 🔴

Что находит: «сиротские» движения (регистратор удалён) и отрицательные остатки по счетам/складам/количеству.

Проверка (1С):

// остатки
ВЫБРАТЬ Счёт, Склад, СУММА(КоличествоОстаток)
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки
СГРУППИРОВАТЬ ПО ... ИМЕЮЩИЕ СУММА(КоличествоОстаток) < 0

Результат: отрицательные остатки с документами-виновниками.

D6. Закрытие периода и расхождение БУ/НУ 🔴

Что находит: незакрытые месяцы, невыполненная последовательность расчётов, расхождения сумм БУ и НУ по счетам.

Проверка (1С):

// последовательности и закрытие
ВЫБРАТЬ Период ИЗ РегистрСведений.ЗакрытиеМесяцев
// расхождения
ВЫБРАТЬ Счёт, СУММА(СуммаБУ) - СУММА(СуммаНУ) КАК Разница
ИЗ РегистрБухгалтерии.Хозрасчёты ГДЕ ... СГРУППИРОВАТЬ ... ИМЕЮЩИЕ Разница <> 0

Результат: список незакрытых периодов + топ расхождений по счетам.

НДС — блок «Отчётность»

D7. Счета-фактуры и книги покупок/продаж 🔴

Что находит: счёт-фактура без реализации, реализация без счёта-фактуры, разрывы в нумерации, записи в книге без отражения в учёте.

Проверка (1С):

ВЫБРАТЬ Реализация.Ссылка ИЗ Документ.РеализацияТоваровУслуг КАК Реализация
ГДЕ Реализация.Проведён И Реализация.СуммаНДС > 0
  И НЕ СУЩЕСТВУЕТ (ВЫБРАТЬ 1 ИЗ Документ.СчётФактураВыданный КАК СФ
      ГДЕ СФ.ДокументОснование = Реализация.Ссылка)

Результат: несопоставленные документы, разрывы номеров, суммы расхождений.

Порог: только проведённые документы за период.

ЗУП — блок «Зарплата»

D8. Начисления, взносы и НДФЛ 🟡

Что находит: начисление без взносов, НДФЛ не совпадает с базой, выплаты без ведомости, взносы без начисления.

Проверка (1С):

ВЫБРАТЬ Сотрудник, Период, СуммаНачислений, СуммаВзносов
ИЗ РегистрНакопления.Начисления
// + сравнение с РегистрНакопления.СтраховыеВзносы и НДФЛ
ГДЕ ... СуммаНачислений > 0 И СуммаВзносов = 0

Результат: сотрудники и периоды с расхождением.

Особое: ПДн-риск — ФИО маскируются в отчёте, показываются только табельные номера.

ПроверкаКритерий

Пропуск известных ошибок0 на тестовом наборе (по 3 ошибки на детектор)

Порядок внедрения

ШагДействие
