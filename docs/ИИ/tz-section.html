Назначение раздела

Определяет правила и состав работ по ИИ-модулю портала: проверка баз, поиск ошибок в данных,

поиск потерянных документов, разбор ошибок бухгалтера. Реализация — не начата, документ описывает

требования для исполнителя.

Обязательные требования

№Требование
1ИИ работает исключительно с песочницей (копией базы), созданной 1c-sandbox
2Одновременно — только 1 песочница, привязанная к 1 базе и 1 пользователю
3Вторая попытка запуска ИИ получает ответ: «Песочница сейчас занята, попробуйте через 3 часа»
4В песочнице разрешено только чтение (роль PostgreSQL SELECT)
5Каждый ответ помечен датой среза данных и именем песочницы
6Функция включается администратором в настройках пользователя
7В списке клиентов рядом с именем включённого пользователя отображается значок ИИ
8В кабинете у пользователя с включённым ИИ после создания песочницы появляется кнопка-иконка ИИ с диалогом, заданиями и отчётами
9Все вызовы ИИ фиксируются в аудите (action='ai_task')
10Песочница живёт до 7 дней, далее удаляется автоматически

Механика блокировки песочницы

Запуск ИИ пользователем А
  → песочница sb_<base>_<MMDDHHMM> закрепляется (busy, ttl=3 ч)
Попытка пользователя Б
  → «Песочница сейчас занята пользователем А (задача «<тип>», начата <время>).
     Попробуйте через 3 часа.»
По истечении 3 ч / после «Завершить»
  → блокировка снимается, песочница доступна

Критерии приёмки

  1. ИИ физически не имеет доступа к живой базе (проверяется попыткой подключения — должно быть отказано).
  2. Два пользователя не могут одновременно получить песочницу; второй видит корректный отказ.
  3. В журналах MCP отсутствуют INSERT/UPDATE/DELETE.
  4. Каждый ответ содержит дату среза и имя песочницы.
  5. Бухгалтер без инструкции запускает «Проверить базу» и понимает отчёт.

Сроки и состав

Дорожная карта: roadmap.md — 7–9 недель, из них 60% — детекторы под конфигурации.

Что не входит в задачу

  • Запись/исправление данных через ИИ.
  • Работа ИИ с живой базой.
  • Автоматическое принятие решений за бухгалтера.
  • Обучение модели на данных без маскирования персональных данных.
