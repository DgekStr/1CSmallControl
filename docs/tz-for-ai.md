## 3. Правила работы

1. Файлы писать в UTF-8 (LF), без BOM; на сервер копировать `scp`, затем `sed -i 's/\r$//'` и удаление BOM.
2. Перед выкладкой — `python -m py_compile app.py`; после — `systemctl is-active 1c-portal` и `curl /healthz`.
3. Не трогать `portal.db` без `chown www-data:www-data` после правок.
4. Секреты (пароли кластера, БД) — только в `/etc/1c-portal/*` и таблице `settings`; **в код и git не коммитить** (есть хук, отклоняющий коммит).
5. Версия меняется только по команде пользователя; пуш — только по команде «пуш».
6. В конце задачи: звуковой сигнал и отчёт в Mattermost (если включён): хук `https://chat.dgek.ru/hooks/aguffugycjdw886bsr1ckedude`.

## 5. Проблема модального окна (приоритет 1)

### 5.1. Симптом

В кабинете клиента (`templates/portal.html`, страница `/`) **внизу экрана висит панель/модалка**, которая:

- не закрывается крестиком и кнопкой «Закрыть»;
- остаётся после выхода из кабинета и повторного входа;
- воспроизводится в **чистом браузере и после очистки истории**, то есть **не связана с кэшем**;
- ранее выглядела как окно «Инструкция сервиса», поверх окна «Настройки» (две модалки друг под другом).

### 5.2. Что уже пробовали (все попытки в git-истории)

| Коммит | Действие | Результат |
|---|---|---|
| `389521d` | инструкция как экран внутри модалки настроек | модалка становилась пустой (разметка вставлена вне `<dialog>`) |
| `0be4beb`… | вынос инструкции в отдельную `<dialog id="dlg-help">` | две модалки одновременно, крестик не закрывал |
| `3376c7a` | `onclick="document.getElementById('dlg-help').close()"` на кнопках | не помогло: окно оставалось |

### 5.3. Рабочая гипотеза

Подозреваемый — **полоса статуса заданий** `#job-band` (fixed внизу экрана), которую «страховочный» скрипт показывал при отправке любой формы с `data-job` и не скрывал, если задание не стартовало. Она рендерится в каждом ответе портала, поэтому «переживает» выход и новую сессию.

### 5.4. Что сделать

1. Открыть `https://1c.dgek.ru/` в инкогнито, войти клиентом, **проверить, есть ли панель внизу** (после удаления guard-скрипта).
2. Если панель есть — в DevTools определить её `id`/класс (`#job-band`, `dialog`, `.modal`), прислать скриншот с открытым инспектором.
3. Убедиться, что в `portal.html` **нет** самодельных обработчиков открытия/закрытия модалок; оставить **один** делегированный обработчик:

```js
document.addEventListener('click', function (e) {
  var op = e.target.closest('[data-open]');
  if (op) {
    var id = op.getAttribute('data-open');
    document.querySelectorAll('dialog[open]').forEach(function (d) { d.close(); });
    var dlg = document.getElementById(id);
    if (dlg) { dlg.showModal(); if (window.lucide) lucide.createIcons(); }
    return;
  }
  if (e.target.closest('[data-close]')) {
    var d = e.target.closest('dialog');
    if (d) d.close();
  }
});
document.addEventListener('keydown', function (e) {
  if (e.key === 'Escape') document.querySelectorAll('dialog[open]').forEach(function (d) { d.close(); });
});
```

4. При загрузке страницы принудительно закрыть все диалоги и спрятать полосу:
   `document.querySelectorAll('dialog[open]').forEach(d => d.close()); document.getElementById('job-band')?.setAttribute('hidden','');`
5. Проверить на 1920×1080 и на мобильном разрешении.

### 5.5. Критерии приёмки

- Внизу экрана **нет** ничего лишнего при входе, работе и выходе.
- «Настройки» открываются и закрываются крестиком, кликом по фону и Escape.
- «Инструкция сервиса» открывается **в новой вкладке** (`/help`), кнопка «Закрыть» возвращает в кабинет.
- Две модалки одновременно не открываются.
- Панель прогресса появляется только при реально активном задании и исчезает после завершения.
- Поведение одинаково в Chrome, Яндекс.Браузере и Firefox.
