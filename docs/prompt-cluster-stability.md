# Промпт для ИИ: разбор нестабильности кластера 1С и портала

Роль: ты старший системный инженер по 1С:Предприятие 8.3 (сервер, PostgreSQL) и Linux.
Задача: разобрать причины периодических падений кластера и недоступности баз, предложить
устойчивые решения и проверяемый план внедрения.

## Контекст инфраструктуры

- 1С:Предприятие 8.3.27.2342, сервер Ubuntu, кластер `maincluster` (порт 1541), RAS 1545.
- PostgreSQL Pro 1c-16, базы: `test`, `dgekdb` (инфобаза `dgek_db`), `goncharov2026`, `montes_bp`.
- Публикации: `/var/www/1c/<публикация>/default.vrd`, Apache+mod_1c, портал Flask (посредник /WEB/).
- Пользователи входят через веб-клиент, тонкий и толстый клиент (`.v8i`).
- Портал: `/opt/1c-portal` (systemd `1c-portal`), БД портала sqlite.
- Автовосстановление: `1c-cluster-health.timer` каждые 45 с (порт 1541, rmngr, RAC, rphost).

## Наблюдаемые симптомы (собраны за один день)

1. После перезагрузки ВМ: `srv1cv8` стартует, но `rmngr` не поднимается → порт 1541 закрыт → 503 у всех баз.
2. После ручного перезапуска `srv1cv8` из админки: ошибка
   «Could not find an available working process on 1C:Enterprise server. Attempts: 5».
3. База создаётся, но через время перестаёт открываться: в логе PostgreSQL
   «Пользователь не прошёл проверку подлинности… Пароль не подходит» — рассинхрон пароля роли БД
   и записи кластера (наблюдалось у `goncharov`, `test`, `goncharov2026`).
4. Инфобаза с «собственным администратором ИБ» не удаляется и не управляется кластерным админом:
   `rac infobase drop` → «Недостаточно прав пользователя на информационную базу», при этом
   `rac infobase update` блокируется сообщением «Информационная база имеет непустой список соединений».
5. «Отключить всех» не снимало сеансы: фоновые задания 1С перезапускаются сразу после terminate.
6. Ручная правка реестра `1CV8Clsto.lst`/`1CV8Clst.lst` (счётчики элементов) дважды ломала кластер;
   восстановление из бэкапа требовало остановки 1С.
7. Автовосстановление само провоцировало серию перезапусков: один таймаут `rac` (10 с) трактовался
   как авария, перезапуск шёл во время ручной операции → двойной перезапуск и длительная недоступность.
8. После импорта `.dt` запускается переиндексация полнотекстового поиска: рост CPU до 80% rphost,
   рост каталога `1Cv8FTxt` на гигабайты, заполнение системного диска (89%).
9. `goncharov2026` периодически теряет доступ: пароль БД рассинхронизируется после перезапусков.

## Что уже сделано (учитывай как исходные данные)

- healthcheck: 1541 + rmngr + RAC + rphost, перезапуск только после 2 подряд сбоев, пропуск при lock.
- `1c-verify-base <ib> <db> <role>`: сброс пароля роли + `rac infobase update` + проверка psql.
- `1c-heal-bases`: после восстановления кластера синхронизирует пароли всех баз из `portal.db`.
- `1c-kick-sessions`: разрешение инфобазы через `infobase summary list` (без `cluster list`).
- Публикации по имени инфобазы; `.v8i` и шлюз правятся на `ib_name`.

## Вопросы к разбору

1. Почему `ragent` поднимается без `rmngr` и как сделать запуск детерминированным
   (unit-зависимости, ExecStartPost-проверка 1541, `Type=notify`/таймауты)?
2. Почему 1С теряет пароль БД при перезапуске службы: гонка записи в реестр, блокировка,
   особенности 2342? Как гарантировать согласованность (идемпотентный heal при старте, мониторинг).
3. Ошибка «Could not find an available working process»: диагностика rphost (память, лимиты,
   `-maxmem`, количество процессов), как не отдавать трафик до готовности rphost.
4. Правильный порядок действий с ИБ, у которой свой администратор ИБ: как удалить/изменить
   без правки реестра руками (использовать консоль, IB-админа, `--infobase-user`), что делать,
   если пароль неизвестен.
5. Регламент «отключить всех»: как гарантированно завершить фоновые задания
   (`scheduled-jobs-deny`, terminate по кругу, проверка 0 сеансов) и не мешать работе.
6. Индексация полнотекстового поиска: когда её отключать, как ограничить рост диска,
   как чистить осиротевшие `1Cv8FTxt` без риска.
7. Политика healthcheck: как отличить «1С ещё стартует» от «1С упала», чтобы не усиливать аварию.
8. Метрики и алерты (что именно мерить: 1541, rmngr, rphost, ошибки авторизации PG, сеансы,
   свободное место, длительность импорта/индексации) и пороги.

## Требования к ответу

1. Таблица: симптом → корневая причина → вероятность → подтверждающая команда/лог.
2. Для каждой причины — решение (конфиг/скрипт/процедура) и способ проверки.
3. Порядок внедрения по приоритету (сначала то, что убирает простой), с оценкой риска.
4. Готовые команды/фрагменты systemd/sudoers/скриптов (без секретов, плейсхолдеры).
5. Явно перечисли, чего делать нельзя (правка реестра вручную, удаление БД при живых сеансах,
   безусловный перезапуск кластера по одному сбою).
