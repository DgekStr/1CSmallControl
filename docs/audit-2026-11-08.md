## 1. Промт для ИИ-агента

**Роль.** Ты — старший инженер по безопасности и эксплуатации веб-сервиса на Flask
(портал доступа к 1С, Ubuntu 22.04, PostgreSQL Pro 16, nginx-прокси, Apache + 1cws).
Работаешь по репозиторию `1CSmallControl` и серверу `192.168.0.5`.

**Запреты.**

- Не менять версию портала (`APP_VERSION`) и не пушить в git без отдельной команды.
- Не выполнять необратимые действия (drop database, вывод узлов кластера, стирание дисков,
  `VACUUM FULL`, `REINDEX`) без подтверждения.
- Не трогать боевые базы 1С (`dgek`, `monesbuh`, `goncharov`) иначе как чтением.
- Не отключать пользователей от 1С без явного разрешения.
- Не печатать в отчёт секреты, пароли, токены, содержимое `/etc/1c-portal/*.conf`.
- Не менять схему БД без миграции, совместимой со старой версией.

**Этап A — инвентаризация и подтверждение находок (без правок).**
Собрать: список маршрутов Flask, все вызовы `subprocess`/`sudo`, работу с файлами и путями,
все места, где проверяется роль, все SQL-запросы с конкатенацией, состояние сервера
(порты, службы, sudoers, systemd-таймеры, cron). Для каждой находки — воспроизведение
(команда + ожидаемый/фактический результат). Итог: таблица «ID → подтверждена/опровергнута».

**Этап B — исправление по приоритету.**
Порядок строго: критичные → высокие → средние. Каждое исправление — отдельный коммит,
сообщение вида `fix(security): S-08 …`. После каждого — прогон проверок из §6.
Никаких «заодно переписал полпроекта».

**Этап C — верификация и отчёт.**
Повторить проверки этапа A (находка должна быть закрыта), снять метрики p50/p95/p99
для страниц кабинета и админки, отправить отчёт в Mattermost, приложить diff-сводку.

**Критерии приёмки.**

1. Каждая находка имеет статус: закрыта / принят риск (с обоснованием) / отложена (с датой).
2. S-08, S-04, S-03, S-01, S-02, S-05 закрыты и проверены воспроизведением.
3. Кабинет клиента: p95 < 500 мс, p99 < 1 с (замер на сервере, 100 запросов).
4. Все длительные операции видны в `/admin/jobs` с логом и прогрессом.
5. `pytest` (или smoke-скрипт) проходит: вход, кабинет, доступ к базе, песочница, 2FA.
6. Отчёт в MM: что сделано, чем проверено, что осталось, риски.

## 4. Находки

### 4.1 Безопасность (20)

| ID | Уровень | Находка | Статус |
|---|---|---|---|
| S-01 | Высокий | `X-Forwarded-For` принимался от любого клиента → обход блокировки подбора пароля | **исправлено**: XFF только от доверенных прокси (127.0.0.1, ::1, 192.168.0.15, 192.168.0.5) |
| S-02 | Высокий | `www-data` имеет sudo на `psql` от `postgres` — любой дефект в портале даёт доступ ко всем базам | план: сузить до конкретных `psql -c` или убрать, вызывать через setuid-хелпер |
| S-03 | Высокий | Переключение режима PostgreSQL (fsync/autovacuum) — сильнодействующая операция, влияет на весь кластер | план: только `admin_required` + подтверждение + TTL-автовозврат (уже есть скрипт) |
| S-04 | Высокий | Создание песочницы принимало любой дамп из `/mnt/1cbackup/` → восстановление чужой базы | **исправлено**: разрешены только копии своей базы (`_sandbox_copies(db_name)`) |
| S-05 | Высокий | Песочница создаётся с ролью `SUPERUSER` и без `--scheduled-jobs-deny=on` → восстановленная база может писать в кластер | план: роль `NOSUPERUSER`, deny scheduled jobs, отключить регламентные задания |
| S-06 | Средний | Пароль кластера 1С и SMB-креды читаемы всеми, кто попал в группу www-data | план: отдельный пользователь-раннер для скриптов, `chmod 400` + `sudo` от него |
| S-07 | Средний | Сессии 1С отключаются по имени базы без проверки принадлежности клиенту | план: проверять `access` перед kick |
| S-08 | **Критично** | Обход прав: `/WEB/<slug>/../<другая>/` → Werkzeug отдаёт `rest='../test/'`, Apache 8081 нормализует путь и открывает чужую публикацию (подтверждено 200) | **исправлено**: `..` в `rest`, `/` и `\` в slug → 404 + журнал `web_traversal` |
| S-09 | Средний | Нет ограничения размера тела запроса в портале (nginx есть, портал — нет) | план: `MAX_CONTENT_LENGTH` |
| S-10 | Средний | CSV/логи с IP и логинами хранятся без ротации по размеру (только logrotate системы) | план: ротация + срок хранения |
| S-11 | Средний | Отсутствует CSP и `X-Frame-Options` на страницах портала | план: заголовки в after_request |
| S-12 | Средний | QR-токен живёт 120 с и не привязан к сессии инициатора | план: привязка к session id + одноразовость (уже одноразовый) |
| S-13 | Низкий | Коды восстановления 2FA не показываются повторно (риск потери) | принято: показываются один раз, есть отключение паролем |
| S-14 | Низкий | В журнале аудита нет user-agent | план: добавить |
| S-15 | Низкий | `DEBUG`-подобные сообщения об ошибках скриптов попадают клиенту (первые 200 символов вывода) | план: клиенту — общий текст, детали в журнал |
| S-16 | Низкий | Нет ограничения на число песочниц в сутки на клиента (есть только одновременных) | план: суточный лимит |
| S-17 | Низкий | Скачивание `.v8i` отдаёт внутренний адрес сервера (задумано), но без подписи | принято |
| S-18 | Низкий | `audit()` не пишет в отдельный файл (только SQLite) | план: дублировать в файл |
| S-19 | Низкий | Нет проверки целостности дампа перед удалением старых копий | план: `pg_restore -l` в retention |
| S-20 | Низкий | Пароль `postgres` для psql-хелпера в файле (не в vault) | принято (локальный сервер), план — переход на peer-auth |

## 6. Проверки

**Безопасность (ручные, воспроизводимые).**

```bash
# S-08: обход прав должен вернуть 404
curl -s -o /dev/null -w '%{http_code}\n' -b cookie.txt 'http://127.0.0.1:8080/WEB/test/../dgek/'
# S-04: чужой дамп не должен приниматься
curl -s -b cookie.txt -d 'csrf=…&dump=/mnt/1cbackup/dgek-…dump' http://127.0.0.1:8080/bases/9/sandbox
# S-01: подделка XFF не должна менять IP в журнале
curl -s -H 'X-Forwarded-For: 1.2.3.4' http://127.0.0.1:8080/login
```

**Производительность.**

```bash
# кабинет и админка: 100 запросов, p50/p95/p99
ab -n 100 -c 1 -b cookie.txt http://127.0.0.1:8080/
# медленные запросы
su - postgres -c "psql -Atc \"select round(total_exec_time/calls) ms, calls, left(query,60)
  from pg_stat_statements order by total_exec_time/calls desc limit 10\""
```

**Функциональные (smoke).** вход/2FA/QR, кабинет, открытие базы, копии, создание/удаление
песочницы, передача, архив, мониторинг, журнал заданий.

## 7. Что проверить с root

| Что | Зачем |
|---|---|
| `visudo -c`, `/etc/sudoers.d/*` | сузить права www-data (S-02, S-06) |
| `ss -tlnp` | не слушает ли что-то лишнее (1545, 8081, 8080) |
| `ufw status` | правила доступа к 1С/PG |
| `systemctl list-timers --all` | все таймеры: бэкап, мониторинг, песочницы |
| `/etc/cron.d/*`, `crontab -l` | бэкап portal.db, чистка |
| `nginx -T` (192.168.0.15) | `default_server`, `auth_request`, лимиты, TLS |
| `/etc/apache2/1c-publications/*.conf` | `Alias`/`SetHandler` — нет ли лишних публикаций |
| `/var/www/1c/*/default.vrd` | `ib=` соответствует нужной инфобазе |
| `rac infobase summary list` | нет висячих инфобаз (были дважды) |
| `ls -la /etc/1c-portal/` | права на секреты (640/600) |
| `pg_hba.conf` | кто и откуда может ходить в PG |
| `postgresql.conf`/`auto.conf` | autovacuum, locks, preload, work_mem |
| `ls /var/log/1c-portal/` | логи заданий: рост, ротация |
| `journalctl -u 1c-portal` | ошибки 500/403 за неделю |
| `du -sh /mnt/1cbackup`, `df -h` | место, ретеншн |
| `/etc/systemd/system/1c-*.service` | `User=`, `Environment=`, лимиты |
