# Архивация баз 1С

Настройка: портал → **«Настройка» → «Архивация баз»**.

## Что делает

1. По расписанию (по умолчанию **04:00 МСК**) делает полный дамп каждой базы PostgreSQL:
   `pg_dump -Fc` → отдельный файл `<база>-YYYYMMDD-HHMM.dump`.
2. Складывает файлы в каталог хранения: локальный путь или сетевая папка SMB
   (`//192.168.0.79/backup/1cbackup`).
3. Удаляет старые копии: на каждую базу хранится N последних (по умолчанию 14).
4. Пишет статус в `/etc/1c-portal/backup-status.json` — его показывает портал
   (свободное место, последний запуск, файлы).

## Как устроено

| Компонент | Назначение |
|---|---|
| `/usr/local/bin/1c-backup` | сам бэкап: монтирование SMB, дампы, ротация, статус |
| `/usr/local/bin/1c-backup-info` | JSON для портала: каталог, свободное место, последний запуск |
| `1c-backup-tick.timer` | запускается **каждую минуту**, вызывает `1c-backup auto` |
| `1c-backup auto` | сработает только когда время совпало с настройкой и сегодня ещё не было |

Такой «tick» нужен, чтобы время запуска и число копий менялись из интерфейса,
без правки cron и перезапуска таймера.

## SMB

- Учётные данные хранятся в `/etc/1c-backup/smb.cred` (600 root).
- Монтируется в `/mnt/1cbackup` с правами пользователя `postgres`, чтобы `pg_dump` писал напрямую.
- Перемонтируется при каждом запуске.

## Проверка

```bash
/usr/local/bin/1c-backup run          # выполнить сейчас
/usr/local/bin/1c-backup-info         # статус в JSON
systemctl list-timers 1c-backup-tick.timer
tail -20 /var/log/1c-backup.log
```

## Ограничения

- Копии лежат в одном месте (SMB-сервер 192.168.0.79). Для полной защиты от потери
  нужно второе место (внешний диск/облако).
- Дампы не шифруются — доступ к папке ограничен учётной записью SMB.
