# Безопасность: сервер 1С и портал

Состояние на 2026-11-07 после аудита. Проект в продакшне, поэтому всё перечисленное проверено на живой системе.

## Схема доступа

```
Интернет ──► nginx 192.168.0.15:443 (TLS, HTTP/2) ──► 192.168.0.5:80 (портал)
Дом / VPN ──► WireGuard 10.1.17.0/24 ──► 192.168.0.5:1541 (тонкий клиент), 1947 (лицензии)
Офис ──► 192.168.0.0/24 ──► 1541, 1560-1591, 1947, 80, 22
```

Наружу открыт **только 443** (на прокси). Порты 1С и лицензий в интернет не публикуются.

## Матрица портов на 192.168.0.5

| Порт | Сервис | Кому |
|---|---|---|
| 22 | SSH | LAN, VPN |
| 80 | Apache (портал) | LAN, VPN (снаружи — через nginx) |
| 1541 | кластер 1С (клиенты) | LAN, VPN |
| 1560-1591 | рабочие процессы 1С | LAN, VPN |
| 1947 | менеджер лицензий HASP | LAN, VPN |
| 1540, 1545 | администрирование 1С (ragent, ras) | **только localhost** |
| 5432 | PostgreSQL | **только localhost и собственный IP** |
| 8080, 8081 | gunicorn, внутренний Apache | только 127.0.0.1 |

## Что сделано

- `ufw` включён: deny incoming, правила только для LAN 192.168.0.0/24 и VPN 10.1.17.0/24.
- Webmin (порт 10000) — **удалён** (`apt purge`).
- PostgreSQL: `listen_addresses = localhost,192.168.0.5`, `pg_hba` — только localhost и собственный адрес (было `0.0.0.0/0 md5`).
- 1С: зарегистрирован администратор кластера `arshin`, пароль разрешён только с localhost; без аутентификации `rac` отвечает «Администратор кластера не аутентифицирован».
- Все служебные скрипты портала (`1c-sessions-count`, `1c-jobs-deny`, `1c-base-state`, `1c-create-base`, `1c-kick-sessions`, `1c-licenses`) передают `--cluster-user/--cluster-pwd` из `/etc/1c-portal/1c-session-admin.conf` (640 root:www-data).
- Портал: `ProxyFix` + `SESSION_COOKIE_SECURE` — сессия только по HTTPS.
- Защита входа: 5 неудачных попыток → блокировка на 15 минут, уведомление в Mattermost (хук в `PORTAL_MM_LOGIN_HOOK`).
- `fail2ban` для SSH (5 попыток → 1 час).
- SSH: `PermitRootLogin prohibit-password`, `MaxAuthTries 4`.
- Права: `/opt/1c-portal` — 770 root:www-data, код 640 (раньше было 777), `portal.db` и `.secret_key` — 600 www-data.
- Бэкапы: 1С-базы ежедневно 02:00 (`/etc/cron.d/1c-db-backup`), база портала 03:00 (`/etc/cron.d/1c-portal-backup`, хранение 14 дней).

## Секреты: правила

- Пароли, токены вебхуков и ключи **не хранятся в git**. Только на сервере:
  - `/etc/1c-portal/1c-session-admin.conf` (640 root:www-data) — доступ к кластеру 1С;
  - `/etc/1c-portal/settings.json` (640 root:www-data) — параметры портала, включая хук Mattermost;
  - `/etc/1c-backup/smb.cred` (600) — учётные данные SMB.
- В репозитории стоит **pre-commit hook** (`.githooks/pre-commit`): коммит с паролем, токеном вебхука
  или приватным ключом отклоняется.
- 2026-11-07: пароль администратора кластера был случайно закоммичен, GitHub прислал предупреждение.
  Пароль **сменён**, файлы с ним удалены из истории (`git filter-branch`), ветка перезаписана.
