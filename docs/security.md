# Аудит безопасности портала 1С

## Что проверено и закрыто

| Проверка | Результат |
|---|---|
| Неудачные попытки входа | 5 попыток → блокировка 15 минут + сообщение в Mattermost |
| Пароли в БД | PBKDF2 (Werkzeug), в открытом виде не хранятся |
| Сессия | подписанная cookie, `Secure`, `HttpOnly`, `SameSite=Lax`, 8 часов |
| CSRF | токен во всех формах, проверяется на POST |
| Роли | все 27 маршрутов `/admin/...` закрыты `admin_required`, клиент получает 403 |
| Панель сервиса | у клиентов нет доступа; в «Доступах» у каждой карточки стоит метка «без доступа к панели сервиса» |
| Вход администратора | пароль или **QR-код** (одноразовый, 120 секунд, подтверждение только с устройства, где уже выполнен вход администратора) |
| Открытые порты | `ufw`: 443 наружу, 1С и лицензии — LAN и VPN, администрирование 1С и PostgreSQL — только localhost |
| Webmin | удалён (порт 10000 закрыт) |
| Администратор кластера 1С | пароль, аутентификация только с localhost |
| SSH | `PermitRootLogin prohibit-password`, `fail2ban` для SSH |
| Права файлов | `/opt/1c-portal` 770 root:www-data, код 640, `portal.db` и `.secret_key` 600 |
| Секреты | не в git; pre-commit hook блокирует коммит с паролем или токеном |

## Секреты: правила

- Пароли, токены вебхуков и ключи **не хранятся в git**. Только на сервере:
  - `/etc/1c-portal/1c-session-admin.conf` (640 root:www-data) — доступ к кластеру 1С;
  - `/etc/1c-portal/settings.json` (660 root:www-data) — параметры портала, включая хук Mattermost;
  - `/etc/1c-backup/smb.cred` (600) — учётные данные SMB.
- В репозитории стоит **pre-commit hook** (`.githooks/pre-commit`): коммит с паролем, токеном вебхука
  или приватным ключом отклоняется.
- 2026-11-07: пароль администратора кластера был случайно закоммичен, GitHub прислал предупреждение.
  Пароль **сменён**, файлы с ним удалены из истории (`git filter-branch`), ветка перезаписана.

## Двухфакторный вход (2FA)

TOTP-код из приложения-аутентификатора: Google Authenticator, Microsoft Authenticator, Яндекс Ключ.

- Включается галочкой: **Настройка → Двухфакторный вход → Включить 2FA**.
- При включении показывается QR для приложения и 10 кодов восстановления (каждый — одноразовый).
- При входе после пароля портал спрашивает шестизначный код; окно подтверждения — 5 минут.
- Отключить можно кодом из приложения **или** паролем портала.
- Реализация без внешних зависимостей: HMAC-SHA1 (RFC 6238), окно ±30 секунд.

## Вход по QR-коду

Доступен **всем пользователям**, как альтернатива логину и паролю.

1. На компьютере открыть `/login` → «Вход по QR-коду».
2. Портал создаёт одноразовый токен (32 байта, живёт 120 секунд) и показывает QR.
3. Телефон, где уже открыт портал под своей учётной записью, сканирует код → подтверждение
   с IP и устройством компьютера.
4. Компьютер опрашивает `/qr/status` и после подтверждения получает сессию.

Ограничения:
- подтвердить может только авторизованный пользователь — токен привязывается к его учётной записи;
- токен одноразовый, повторный вход по нему невозможен;
- все шаги пишутся в журнал: `qr_start`, `qr_approve`, `qr_login`.

## Вход администратора по QR-коду

Зачем: администратору не нужно вводить пароль на чужом или общем компьютере.

1. На компьютере открыть `/login` → «Вход администратора по QR-коду».
2. Портал создаёт одноразовый токен (32 байта, живёт 120 секунд) и показывает QR.
3. Телефон, где уже открыт портал под администратором, сканирует код → страница подтверждения
   с IP и устройством компьютера → «Подтвердить вход».
4. Компьютер опрашивает `/qr/status` и после подтверждения получает сессию администратора.

Ограничения:
- подтвердить может только пользователь с ролью `admin`;
- токен одноразовый, повторный вход по нему невозможен;
- просроченные токены чистятся автоматически (старше часа);
- все шаги пишутся в журнал: `qr_start`, `qr_approve`, `qr_login`.

Зависимость: `qrencode` (пакет apt), генерация локальная — внешние сервисы не используются.
