# Новый сервер 1С: план переезда

**Статус:** согласовано. **Команда запуска:** произнести «новый сервер» — начинаем выполнять
этот план с этапа 0, далее по списку с контролем после каждого этапа.

Дата фиксации: 6 ноября 2026. Последнее обновление: **20 ноября 2026** (сборка на Ryzen 9 3900X,
тестирование дома на изолированном сегменте, покупка дисков).

## 1. Цель

Перенести сервер 1С с текущей виртуальной машины (Xeon L5520, 2009 г.) на выделенное железо
(AMD Ryzen 9 3900X) и получить:

| Показатель | Сейчас | После переезда |

| Обновление конфигурации | ~6 часов | ~2 часа |
| Открытие форм и интерфейс | 2–4 с | 0,7–1,5 с |
| Одновременных пользователей | 3–5 с очередями | 5–10 без заметных задержек |

## 4. Домашний стенд: изолированный сегмент 192.168.0.0/24

Задача — протестировать клон боевой ВМ **с тем же IP `192.168.0.5`**, не меняя конфигурацию 1С,
портала и публикаций. Домашняя сеть `192.168.88.0/24` при этом не пересекается с тестовой.

```
Домашний роутер 192.168.88.1
      │
  vmbr0 (1-я сетевая) — хост 192.168.88.20
      │
  Proxmox ── vmbr1 (2-я сетевая, enp3s0) ── коммутатор
      │                                       ├─ ВМ-клон 913   192.168.0.5
      │                                       └─ тест-ПК      192.168.0.10
```

| Узел | Адрес | Примечание |
|---|---|---|
| Proxmox, домашняя сеть | `192.168.88.20` | vmbr0, шлюз `192.168.88.1` |
| Proxmox, тестовый сегмент | `192.168.0.1` | vmbr1 |
| **ВМ-клон 1С** | **`192.168.0.5/24`**, шлюз `192.168.0.1` | как боевая |
| Тест-ПК | `192.168.0.10/24`, шлюз `192.168.0.1` | на коммутаторе |

### Настройка vmbr1

```bash
ip a                    # найти имя второй сетевой карты (например enp3s0)
```

`/etc/network/interfaces`:

```ini
auto vmbr1
iface vmbr1 inet static
    address 192.168.0.1/24
    bridge-ports enp3s0
    bridge-stp off
    bridge-fd 0
```

```bash
ifreload -a
```

ВМ-клону: `qm set 913 --net0 virtio,bridge=vmbr1`. Внутри клона оставить `192.168.0.5/24`,
шлюз `192.168.0.1` — конфигурация 1С/портала не меняется.

### Интернет внутри клона (только при необходимости)

```bash
sysctl -w net.ipv4.ip_forward=1
iptables -t nat -A POSTROUTING -o vmbr0 -j MASQUERADE
```

## 5. Лицензии HASP при тестировании

| Что | Как |
|---|---|
| Клиентские лицензии (5 мест) | ключ `H4 nets5 orgl8` — подключить к ВМ через USB passthrough (`qm set 913 -usb0 host=0529:0001`) **или** оставить в Windows-ПК на тестовом сегменте и прописать `nethasp.ini` → `192.168.0.10` |
| Проверка | внутри клона: `ls /etc/usbhaspd/keys/`, `/usr/local/bin/1c-licenses` → ожидаем `0 5 5 0` |
| **Серверная лицензия** | домашние 5-местные ключи — **клиентские**; для `rphost` нужна серверная (на боевой — `EN8SA`/`ENSR8`). Проверить запуск `srv1cv8`; если лицензии нет — временно перенести серверный ключ или тестировать частично |

## 6. Порядок работ

| Этап | Действие | Простой | Критерий готовности |
|---|---|---|---|
| **0** | Снять `vzdump` ВМ 213 на pve2, скопировать на новый узел, восстановить клон (ID 913) | нет | клон открывается, БД поднимается |
| **1** | Проверить железо: SMART дисков, порты SATA, память (memtest), BIOS | нет | отчёт SMART без ошибок |
| **2** | Установить Proxmox VE **8.4** (не 9) на новый сервер, vmbr0/vmbr1 | нет | `pveversion` = 8.4.x |
| **3** | **Тест дома** на изолированном сегменте: 1С, PostgreSQL, портал, бэкапы, лицензии | нет | вход в базу, отчёты, 5 сеансов |
| **4** | Переезд в серверную: боевой IP хоста, коросинк `10.10.10.4` | нет | сеть и связь с кластером есть |
| **5** | Ввод узла в кластер `pvecm add` | нет | 4 узла, Quorate: Yes |
| **6** | Окно: миграция ВМ 213 на новый узел с дисками | 15–40 мин | ВМ запущена, 1С и портал отвечают |
| **7** | Проверка, снапшот, возврат ключей | нет | чек-лист пройден |

## 7. Ввод узла в кластер — важное предупреждение

**Не вводить в кластер узел, на котором уже есть ВМ.** При `pvecm add` локальная база `/etc/pve`
заменяется кластерной: конфиги локальных ВМ пропадают из интерфейса (диски при этом целы).
Если это уже случилось — восстановление:

```bash
ls /etc/pve/nodes/*/qemu-server/     # возможно, конфиги на месте под старым именем узла
lvs | grep vm-; zfs list | grep vm-  # диски целы
qm create 901 --name test --memory 8192 --cores 4 --net0 virtio,bridge=vmbr0
qm rescan --vmid 901                 # найдёт неиспользуемые диски
qm set 901 --scsi0 unused0           # подключить диск
```

Правильный порядок для нового узла: **сначала тест дома, потом переезд, потом ввод в кластер**,
когда на узле нет нужных локальных ВМ.

### Команды ввода

```bash
# на новом узле, PVE 8.4, имя pve4
pvecm add 192.168.0.18 -link0 10.10.10.4
pvecm status          # ожидаем 4 узла, Quorate: Yes
```

**IP-адреса:** хост нового узла — свободный боевой адрес (не `.5`, не `.15`, не `.16/.18/.19`,
не `.20`), например `192.168.0.21`. Коросинк — `10.10.10.4` (vmbr1, 10.10.10.0/24).

## 8. Миграция ВМ 213

```bash
# вариант А: офлайн-миграция в окно
qm shutdown 213
qm migrate 213 pve4 --with-local-disks
qm start 213

# вариант Б: репликация ZFS и короткое переключение
pvesr create-local-job 213-0 pve4 --schedule '*/15'
qm migrate 213 pve4 --with-local-disks --online
```

После переезда IP гостя остаётся `192.168.0.5`, старая ВМ не включается.

## 9. Проверка после переезда

```bash
qm status 213
systemctl is-active srv1cv8 postgrespro-1c-16 apache2 1c-portal
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/WEB/dgek_db/
pvecm status
```

Ожидаем: 4 узла, Quorate: Yes; 1С и портал отвечают 200; лицензии видны (`1c-licenses`).

## 10. Настройки ZFS и бэкапы

| Параметр | Значение |
|---|---|
| `ashift` | 12 (4K-сектора SSD) |
| `compression` | `lz4` |
| `recordsize` | `16k` для томов БД |
| `zfs_arc_max` | ~8 ГБ |
| Пул под ВМ | mirror из двух NVMe (или отдельный пул для клона) |

Бэкапы: NVMe-миррор → ежедневные дампы PostgreSQL в `backup_dir` → HDD 1 ТБ + CIFS `192.168.0.20`.
Правило 3-2-1 сохраняется.

## 11. Риски и откат

| Риск | Снижение |
|---|---|
| Ошибка при миграции ВМ | снапшот/`vzdump` до миграции, старый узел не выводим |
| Отказ NVMe | миррор из двух дисков |
| Потребительская плата без ECC | ИБП, бэкапы, контроль SMART |
| Потеря лицензий 1С | ВМ переносится целиком, ключи остаются на месте |
| Долгий простой | окно ночью, отлаженный клон, откат на старую ВМ |
| Два хоста с IP `.5` | боевая ВМ 213 выключается до включения новой |

## 14. Команда запуска

Фраза **«новый сервер»** означает: начать выполнение плана с этапа 0 (клон ВМ), далее по списку
с контролем после каждого этапа. Без отдельного разрешения не выполнять необратимые шаги
(стирание дисков, вывод узлов из кластера, остановка боевой ВМ).
