# Итог диагностики производительности 1С — 14.11.2026

**Статус:** точка зафиксирована. Дальнейшие работы по производительности — после переезда на новый сервер (NVMe).

## 1. Главный вывод

Причина медленного входа в 1С (до 2 минут от ввода пароля) и медленного восстановления баз —
**дисковая подсистема виртуальных машин Proxmox: ~25 синхронных операций в секунду (fsync-IOPS)**.

| Тест | Результат |
|---|---|
| Последовательная запись (`dd`, direct, 512 МБ) на `/` | **578 МБ/с** — выглядит нормально |
| Случайная запись с fsync (200×1 МБ) на `sda` | 8 225 мс → **24 IOPS** |
| То же на `sdb` (`/var/lib/pgpro`) | 3 513 мс на 100 МБ → **28 IOPS** |
| Норма для SSD | **1 000+ IOPS** |
| `pg_restore` дампа | **~0,7 МБ/с** (не завершился за часы) |

PostgreSQL на такой подсистеме тратит десятки миллисекунд на каждый `commit`. При входе в базу
1С выполняет сотни таких операций (загрузка конфигурации, сеанс, кэши) → суммарно минуты.
CPU, RAM, сеть при этом свободны — отсюда парадокс «тормозит на ровном месте».

**Почему «сначала было быстро, а потом стало медленно»:** базы выросли (1,7–3 ГБ), I/O-нагрузка
выросла кратно, и система упёрлась в потолок ~25 IOPS, а не в мощность сервера.

| Слой | Проверка | Вердикт |

## 3. Что было применено

| Действие | Состояние | Откат |
|---|---|---|
| **`synchronous_commit = off`** (PostgreSQL) | применено | `ALTER SYSTEM RESET synchronous_commit; SELECT pg_reload_conf();` |
| Порядок старта HASP: `usbhaspd → USB-ready → aksusbd → hasplm` | устранён флуд `990364755` | — |
| Восстановление сетевого HASP (`nethasp.ini`, `hasplm.conf`) | ключ `net100` снова выдаётся | бэкапы `*.bak.2345` |
| Песочница `sbx_mp` | удалена (restore не укладывался из-за IOPS) | — |

Замер после `synchronous_commit=off`: **1000 вставок + commit = 53 мс** (было в разы дольше).

## 4. Остаточные риски

| Риск | Оценка |
|---|---|
| `synchronous_commit=off` | при аварии сервера теряются последние ~200 мс транзакций; для текущей нагрузки приемлемо |
| Диски ~25 IOPS | любые тяжёлые операции (restore, реиндексация, обновление конфигурации) остаются медленными |
| Флуд `990364755` | устранён, но вернётся при неправильном порядке старта HASP после ребута — следить за `error.log` |
| Фантомная инфобаза `goncharov` | запись в кластере без БД; удаляется только через консоль 1С |

## 5. Что дальше — новый сервер

План: `docs/Server/new-server-plan.md`. Ключевое изменение — **SQL на NVMe**:

| Диск | Назначение |
|---|---|
| SSD SATA | Proxmox + диски ВМ |
| **NVMe 1 ТБ (Samsung 970 EVO Plus) в M.2** | **SQL / PostgreSQL** (10 000+ IOPS) |
| NVMe 240 через PA19 (x16) | ZFS — быстрый резерв баз |
| HDD 1 ТБ | архив/копии |

Закупка: NVMe 1 ТБ (~13 000 ₽), адаптер GLOTRENDS PA19 (~2 500 ₽), память 2×32 ГБ DDR4-3200
(~22 000–25 000 ₽), опционально i9-10850K/10900K (~15 000–20 000 ₽).
