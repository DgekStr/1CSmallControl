# Новый сервер 1С: предложение и план переезда

**Статус:** согласовано. **Команда запуска:** произнести «новый сервер» — начинаем выполнять
этот план с этапа 0.

Дата фиксации: 6 ноября 2026.

## 1. Цель

Перенести сервер 1С с текущей виртуальной машины (Xeon L5520, 2009 г.) на выделенное железо
(Intel i7-10700K) и получить:

| Показатель | Сейчас | После переезда |
|---|---|---|
| Обновление конфигурации | ~6 часов | ~2 часа |
| Открытие форм и интерфейс | 2–4 с | 0,7–1,5 с |
| Одновременных пользователей | 3–5 с очередями | 3–5 без заметных задержек |

## 2. Железо

| Компонент | Значение | Комментарий |
|---|---|---|
| Процессор | Intel Core i7-10700K, 8 ядер / 16 потоков, 3,8–4,7 ГГц | ×3 к текущему на поток |
| Материнская плата | Gigabyte H510M H, LGA1200 | 1× M.2, 4× SATA |
| Память | 32 ГБ DDR4-3600, dual channel (2×16) | ВМ 1С забирает 16 ГБ |
| Сеть | 1 GbE Realtek | для кластера желателен второй порт |
| ОС (будет) | **Proxmox VE 8.4** | не 9 — иначе не войдёт в кластер 8.4 |

### Диски и их назначение

| Диск | Состояние | Назначение |
|---|---|---|
| NVMe 240 ГБ Samsung | 98 % | система Proxmox |
| SSD 512 ГБ Kingston | 99 % | диски ВМ, базы 1С |
| HDD 1 ТБ Seagate | — | архив, локальная копия бэкапов |

### Что докупить до начала

1. **Второй SSD 512 ГБ** — в ZFS-зеркало под диски ВМ (обязательно: сейчас базы на одном диске).
2. **ИБП** — обязательно для сервера с 1С.
3. SATA-кабели и питание под дополнительные диски (свободно 2 порта SATA).
4. По желанию: вторая сетевая карта под отдельный линк кластера.
5. По желанию: 64 ГБ ОЗУ, если планируются другие ВМ.

## 3. Кластер

- Кластер: **pve-dgek**, сейчас 3 узла (pve, pve2, pve3), Proxmox **8.4.17**.
- Новый узел ставится с **PVE 8.4** и вводится четвёртым.
- Сеть коросинка: **10.10.10.0/24** (vmbr1), не через 192.168.0.0/24.
- После ввода: кворум 3 из 4 — один узел может выйти без потери кворума.

## 4. Порядок работ

| Этап | Действие | Простой | Критерий готовности |
|---|---|---|---|
| **0** | Скопировать файловые базы 1С со старого сервера на текущий (не перемещать) | нет | копии открываются, размеры совпадают |
| **1** | Проверить железо: SMART дисков, порты SATA, ИБП, модель Kingston | нет | отчёт SMART без ошибок |
| **2** | Установить Proxmox 8.4 на новый сервер, ZFS-пулы | нет | `pveversion` = 8.4.x |
| **3** | Ввести узел в кластер, проверить кворум и сеть | нет | `pvecm status` — 4 узла, Quorate: Yes |
| **4** | Окно выходного дня (с вечера субботы до утра воскресенья): миграция ВМ 213 на новый узел с дисками | 15–40 мин работы, до суток резерва на проверки | ВМ запущена, 1С и портал отвечают |
| **5** | Импорт файловых баз в PostgreSQL на быстром CPU (`.dt` → новая база) | по базам | базы открываются, версии конфигураций верны |
| **6** | Проверка, снапшот, выключить режим ускорения PostgreSQL | нет | чек-лист пройден |
| **7** | Через неделю стабильной работы — обновление кластера до PVE 9 (отдельная задача) | по узлам | кластер на 9.x |

## 5. Команды этапов

### Проверка перед установкой

```bash
smartctl -a /dev/nvme0          # NVMe система
smartctl -a /dev/sda            # SSD базы (Kingston)
smartctl -a /dev/sdb            # HDD архив
```

### Ввод узла в кластер

```bash
# на новом узле, PVE 8.4, имя узла pve4
pvecm add 192.168.0.18 -link0 10.10.10.4
pvecm status          # ожидаем 4 узла, Quorate: Yes
```

### Миграция ВМ 213 с локальными дисками

```bash
# вариант А: офлайн-миграция в окно (простой 15-40 мин на 82 ГБ)
qm shutdown 213
qm migrate 213 pve4 --with-local-disks
qm start 213

# вариант Б: репликация ZFS и короткое переключение
pvesr create-local-job 213-0 pve4 --schedule '*/15'
# после синхронизации: qm migrate 213 pve4 --with-local-disks --online
```

### Проверка после переезда

```bash
qm status 213
systemctl is-active srv1cv8 postgrespro-1c-16 apache2 1c-portal   # внутри ВМ
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/WEB/dgek/
```

## 6. Настройки ZFS

| Параметр | Значение | Зачем |
|---|---|---|
| `ashift` | 12 | 4K-сектора SSD |
| `compression` | `lz4` | сжатие без заметной нагрузки |
| `recordsize` | `16k` для томов БД | под PostgreSQL |
| `zfs_arc_max` | ~8 ГБ | из 32 ГБ, ВМ забирает 16 |
| пул под ВМ | **mirror** из двух SSD | защита от отказа диска |

## 7. Резервное копирование

- **Основной бэкап:** CIFS `backup` на 192.168.0.20 (5,8 ТБ, занято 60 %).
- **Локальная копия:** HDD 1 ТБ в новом сервере (архив).
- **Правило:** 3 копии, 2 носителя, 1 вне сервера; выгрузка `.dt` баз — перед каждым обновлением.
- Расписание: ежедневный бэкап ВМ 1С + еженедельная проверка восстановления.

## 8. Риски и откат

| Риск | Снижение |
|---|---|
| Ошибка при миграции ВМ | снапшот до миграции, старый узел не выводим неделю |
| Отказ Kingston (один диск) | добавить второй SSD в зеркало ДО переезда баз |
| Потребительская плата без ECC | ИБП, бэкапы, контроль SMART |
| Потеря лицензий 1С | ВМ переносится целиком, ключи переезжают с ней |
| Долгий простой | окно ночью, офлайн-миграция, заранее проверенный план |

## 9. Чек-лист перед стартом

- [ ] Копии файловых баз 1С сняты и проверены
- [ ] SMART всех трёх дисков снят, ошибок нет
- [ ] Второй SSD куплен и установлен
- [ ] ИБП подключён
- [ ] Установлен PVE 8.4, узел введён в кластер (4 узла, кворум есть)
- [ ] Снапшот ВМ 213 сделан
- [ ] Согласовано окно выходного дня с пользователями (с вечера субботы до утра воскресенья)
- [ ] Проверено восстановление из бэкапа на тестовой ВМ

## 10. Команда запуска

Фраза **«новый сервер»** означает: начать выполнение плана с этапа 0 (копирование баз),
далее по списку с контролем после каждого этапа.
