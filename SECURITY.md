# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выпускаются для текущей ветки.

| Версия | Поддержка |
|---|---|
| 1.3.x | ✅ активная |
| 1.2.x и ранее | ❌ только в составе обновления до 1.3 |

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Используйте приватный канал:

👉 [Сообщить приватно (GitHub Security Advisory)](https://github.com/DgekStr/1CSmallControl/security/advisories/new)

В обращении укажите:

- версию портала (шапка/подвал) и окружение (ОС, версия 1С, браузер);
- шаги воспроизведения и ожидаемое/фактическое поведение;
- оценку влияния: что можно получить (доступ к чужой базе, данные, выполнение кода);
- при наличии — proof-of-concept.

Ответ — в течение 3 рабочих дней, план устранения — в течение 10 рабочих дней.
О публикации уязвимости договоримся отдельно; указание автора в благодарностях — по желанию.

## Что входит в область проверки

| Область | Примеры |
|---|---|
| Аутентификация портала | обход входа, фиксация сессии, перебор паролей |
| Разграничение доступа | доступ к базе без права, повышение роли до администратора |
| Шлюз публикаций 1С (`/WEB/`) | доступ к публикации без сессии, обход проверки прав |
| CSRF / XSS | подделка запросов, внедрение скриптов в интерфейс |
| Раскрытие данных | утечка паролей, IP, журналов, файлов вне `static/` |
| Обслуживающие скрипты | подмена аргументов скриптов `1c-*.sh`, sudoers |

## Вне области

- атаки, требующие физического доступа к серверу или root-прав;
- уязвимости самой платформы 1С, PostgreSQL, Apache и ОС (сообщайте вендорам);
- социальная инженерия и фишинг;
- отказ в обслуживании при доступе к самому серверу;
- конфигурации с отключённым HTTPS на периметре (ответственность владельца установки).

## Рекомендации по развёртыванию

1. Смените пароль администратора при первом входе.
2. Храните секреты в переменных окружения (`PORTAL_ADMIN_PASSWORD`), а не в коде.
3. Держите `1c-portal`, Apache и PostgreSQL за HTTPS-прокси.
4. Ограничьте доступ к порту 8081 (публикации 1С) только `127.0.0.1`.
5. Регулярно обновляйте зависимости и платформу 1С.

## Раскрытие

Мы публикуем исправления через релизы с тегом (`vX.Y`) и записью в [CHANGELOG](CHANGELOG.md),
при необходимости — с отдельным GitHub Security Advisory.
